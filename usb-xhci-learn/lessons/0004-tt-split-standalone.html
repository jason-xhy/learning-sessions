为什么需要 TT：一个 hub，两个时钟域

先补两个时间词（§5.3.3、§8.4.3）：USB 总线的时间由主机用 SOF（Start Of Frame）包"打拍子"——相邻两个 SOF 之间就是一个调度格。全速总线一格 1 ms，叫帧（frame）：SOF 每 1.00 ms ±0.0005 ms 一个，帧号随帧递增。高速总线把同一毫秒切成 8 格，每格 125 µs，叫微帧（microframe）：SOF 每 125 µs 一个，但帧号仍每 1 ms 才变一次——同一帧内 8 个 SOF 的帧号相同，设备靠比对相邻 SOF 的帧号自己数微帧位置。切细 8 倍的收益：中断/等时的排班粒度从 1 kHz 提到 8 kHz（高带宽端点每微帧还可发 1–3 个事务，§5.9）；周期带宽上限也按各自槽位算——FS ≤90% 帧时间、HS ≤80% 微帧时间（§5.6.4/§5.7.4）。

高速 hub 的上行口跑 HS 域：480 Mb/s、微帧 125 µs；下行口可能挂 FS 设备：12 Mb/s、帧 1 ms（§7.1.11/§7.1.12）。两种信令、两个节拍，hub 里的事务翻译器（Transaction Translator，TT）负责两边互译。规范的做法相当克制：

split 只存在于主机控制器 ↔ hub 之间，设备永远不可见（§5.10、§11.1.1）。hub↔设备一侧仍是普通 FS/LS 事务。设备无需知道任何事——这就是兼容性的代价全由主机侧承担的设计。

量级上：一个 HS 微帧（125 µs）只占 FS 帧（1 ms）的 1/8——翻译的实时性压力全压在 hub 的 TT 缓冲与调度上。

USB 2.0（2024-09-27 版） · p451

This request is only defined for non-periodic endpoints; e.g., if it is issued for a periodic endpoint, the response is undefined. After successful completion of this request, the buffer can again be used by the TT with high-speed split transactions for full-/low-speed transactions to attached full-/low-speed devices.
