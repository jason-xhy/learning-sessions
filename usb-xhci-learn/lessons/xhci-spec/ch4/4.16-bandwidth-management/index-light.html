xHCI 1.2b §4.16 Bandwidth Management · p258–261 · §4.16.1 Bandwidth Negotiation

规范要义

xHCI 不再假设「一条控制器接口=一份 USB 带宽」：厂商可以把根集线器端口组织成任意数量的内部 USB 实例（全体端口共享一份，或每端口独享一份，或任意组合）。带宽评估因此取决于两件事：端口被分到哪个实例、同实例上其它设备已占用多少。

软件用 Configure Endpoint 命令问 xHC「这个配置的带宽够不够」；xHC 按内部组织评估，失败回 Bandwidth Error / Secondary Bandwidth Error。软件可换端点设置重试，或发 Negotiate Bandwidth 命令——它给同一 USB 实例上每台有周期端点的设备生成一张 Bandwidth Request Event，请各家自愿让出带宽。

让带宽没有强制：收到请求的设备驱动可以不理会（好公民才会配合），配合的方式=换配置或备选接口→重新 Configure Endpoint，xHC 随之重算实例可用带宽。Disable Slot 命令会释放该槽周期端点的全部带宽（§4.4 的回收项之一）。

原文对照

“Software uses the Configure Endpoint Command to ask the xHC if the bandwidth required for a specific device configuration is available.”
带宽申请的入口就是 Configure Endpoint 命令——问句式命令，答案在完成事件里。
xHCI 1.2b §4.16 p258
“There is no requirement that a device give up bandwidth due to a Bandwidth Request Event, however a “good citizen” will do their best to comply.”
Bandwidth Request Event 是请求不是命令——让不让带宽是驱动自愿，规范只劝「好公民」。
xHCI 1.2b §4.16.1 p259
“A Disable Slot Command will cause any bandwidth allocated to the periodic endpoints of a device slot to be freed.”
停用槽即释放其周期端点带宽——§4.4 五项回收的带宽项在这里落地。
