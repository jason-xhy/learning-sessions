xHCI 1.2b §4.3 USB Device Initialization · p71–80（§4.3.1–§4.3.8 含）

规范要义

一台设备插入根端口后，登记走一条固定主线：检出插入（USB2 端口先进 Disabled 态）→ 软件写 PORTSC.PR=1 做端口复位——USB2 必须由软件发起，复位完成看 PRC=1、PED=1、PR=0、PLS=U0 四个信号，Port Speed 同时指示设备速度 → Enable Slot 取设备槽 → 软件填输入上下文（A0=1、A1=1）并装载 DCBAA 表项、架好 EP0 传输环 → Address Device（BSR=0）让 xHC 在总线上发 SET_ADDRESS → FS 设备先读描述符前 8 字节拿 bMaxPacketSize0，需要时用 Evaluate Context 更新 EP0 Max Packet Size → 读完整描述符 → Configure Endpoint 与 SET_CONFIGURATION 两个操作都成功，设备与槽同时进 Configured。

三方各管一段：数据结构全由软件准备——输入上下文、EP0 传输环、DCBAA 表项都是软件装载、xHC 只读；xHC 执行命令，并在需要时于总线上代发 USB 请求（SET_ADDRESS、GET_DESCRIPTOR、SET_CONFIGURATION）；设备从头到尾只看见 USB 请求与总线事件，槽/环/上下文对它不可见。规范原文称软件侧为 system software（系统软件），本页统一写「xHCI 驱动」。

三处分支最易混：其一，USB3 端口插入轮询成功自动到 Enabled，USB2 端口必须软件复位才能到 Enabled，且两族的 Disabled 态含义不同；其二，8 字节描述符读取只有 FS 设备必走，LS/HS/SS 默认包长 8/64/512 可跳过；其三，BSR=1 是 legacy 设备分支——先在 Default 态通信、xHC 被禁止发 SET_ADDRESS，成功后槽进 Default 而不是 Addressed。多级拓扑另有逐层要求：每一层的 hub 与 TT 完全初始化后才能处理下一层。

到 Configured 需要双操作同成：Configure Endpoint 命令成功且 SET_CONFIGURATION 请求成功，缺一不可。

分支注记

USB3 端口：自动 Enabled

USB3 协议端口插入后进入 Polling：轮询成功自动到 Enabled（PED=1、PR=0、PLS=0），失败回 Disconnected。注意两族的 Disabled 态不同义——USB3 指 DSPORT.Disabled（USB3 规范图 10-9），USB2 指 USB2 规范 Disabled 态（图 11-10）。
xHCI 1.2b §4.3 p71–72

BSR=1：legacy 设备分支

个别 legacy 设备需要先在 Default 态通信再编址：Address Device 带 BSR=1——EP0 先启用，但 xHC 被禁止发 SET_ADDRESS；成功后槽 Enabled→Default（主线 BSR=0 成功是 Enabled→Addressed）。
xHCI 1.2b §4.3.4 p76–77

hub 与 TT：逐层初始化

多级拓扑必须从根集线器起，把每一层的 hub 与 TT 完全初始化后再处理下一层，否则 xHC 行为未定义。

📎 §4.3.4 BSR=0 主线（p77）

xHCI 1.2b · p77

Successful completion of the Address Device Command with BSR = ‘0’ shall transition the Device Slot from the Enabled to the Addressed state.

BSR=0 成功 → 槽 Enabled→Addressed；BSR=1 是 legacy 分支（槽 Enabled→Default）——内核把 BSR 位编进 TRB 字段 4（SETUP_CONTEXT_ONLY 才置位）。

📎 §3.3.4 命令替代 SET_ADDRESS（p62）

xHCI 1.2b · p62

Execution of the Address Device Command (BSR = ‘0’) causes the xHC to issue a SET_ADDRESS request to the USB device, assigning a unique address to it. This operation causes a USB device that is in the Default state to transition to the Address state.

设备第一次收到 USB 请求——发请求的是 xHC，不是驱动；设备从 Default 迁到 Address 态。

📎 §3.3.4 地址由 xHC 选定（p62）

xHCI 1.2b · p62

Note that the xHC, not software, selects the address that is assigned to the USB device.

驱动只递上下文与槽位号；新地址由 xHC 选定（示例值 1），经 SET_ADDRESS 告知设备，编址完成写进输出上下文由驱动读回。

📎 §4.6.5 USB2 请求发往地址 0（p97）

xHCI 1.2b · p97

The SET_ADDRESS request for a USB2 device shall be issued to Address ‘0’.

设备此刻的地址是复位后的默认地址 '0'——票据沿总线发往 '0'，内容里带着 xHC 选定的新地址。

📎 §3.3.4 成功后拷上下文、EP0 环转 Running（p62）

xHCI 1.2b · p62

If the SET_ADDRESS request issued by the xHC is successful, the contents of the Input Slot and Endpoint 0 Context data structures are copied to the respective Device Context data structures, and the Transfer Ring associated with endpoint 0 is set to the Running state.

编址成功的两个副作用：输入上下文拷入输出上下文（DCBAA 1 号格所指）、EP0 传输环进入 Running——此后门铃 1 可投 TD。

📎 §4.3.3 EP0 上下文初值（p76）

xHCI 1.2b · p76

Max Packet Size = The default maximum packet size for the Default Control Endpoint, as function of the PORTSC Port Speed field.

规范初值按端口速度默认（FS=8）；内核此处对 FS 写 64（USB 核心新方案先按 64 字节试探读描述符）——差异在帧注记里如实登记。

📎 §4.1 命令门铃（p68）

xHCI 1.2b · p68

All xHC commands are issued by placing the desired Command TRB(s) on the Command Ring, then ringing the xHC command Doorbell register, that is, writing the Host Controller Command code to the DB Target field of Doorbell register 0

命令投递＝写环＋写门铃 0，缺一不可；与 EP0 门铃（DB Target=1）语义不同。
