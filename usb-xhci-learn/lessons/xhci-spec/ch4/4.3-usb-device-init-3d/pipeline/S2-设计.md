# S2-设计 —— 场景设计方法论

制定：2026-11-10 ｜ 执行：S2 worker ｜ 需求：S2-需求.md

## 1. 事实→场景映射法（防发明数值的第一道闸）

- **每元素一个锚**：场景中每个承载规范语义的元素（读数屏字段、卡面字段值、灯语义、流转路径）在主件中必须能指回 S1 章节号（间接含 pNN）。写作时以 S1 §1–§7 事实表为清单逐个对号，不以记忆引入。
- **两类值显式分界**：主件 §0 声明——「规范语义值」（字段值/状态名/页码，唯一源=S1）与「设计参数」（几何尺寸/坐标/时长/颜色/卡槽数，S2 自由裁定、标注〔设计参数〕）。凡不声明者默认按规范语义值对待，scorer 可按零发明要求追责。
- **S1 建模提示照单消费**：S1 §8.1 六章建模提示给出画面隐喻与分镜锚，逐条吸收进 §A–§D；提示中未覆盖的画面需求才自行设计，且只设计形态不设计语义。
- **场景约定显式标注**：非规范事实的场景表达（如设备铭牌文案、卡槽数=12）沿用 V1/V2 已核口径或标注「场景约定」，绝不写成规范条文。

## 2. 布局推导法（继承已验证资产，不另起炉灶）

- **坐标系与体量继承 V2**：V2 修复轮实证的资产直接继承——世界坐标（Y 上、+X 东、+Z 向镜头）、三区横跨（文书台 x≈[-19,-12]、机柜中区、设备区 x≈13–17）、F0 机位基线 pos [6.8,12,39]/tgt [6.8,3,0]、视口 ~1024px 口径、≤480px camAdapt（拉远 k=max(1.5,68/d)+目标西移 7）。理由：这些值经三轮评分门+右缘裁剪图人验校准，重推是纯风险。
- **三环层高按两条约束推导**：①入画优先——三环层间距 1.8 世界单位，全景机位仰角下三层在 ~1024px 视口内互不粘叠；②走廊净空——事件环置顶层（y=13.6），脱离段先升后降，飞行路径不穿任何轨道横梁（坐标段写死进 §I，S3/S4 可几何断言）。
- **slot 编号约定统一立法**：每环 12 卡槽〔设计参数，承 V2〕，slot 0=东端、俯视逆时针递增、slot 6=西端；事件入环=slot 1、脱离=slot 6；命令入环=slot 7；EP0 三卡落位=slot 5/6/7、消费点=slot 1。全文档统一此编号，S3 不再各自发明。

## 3. 遮挡预案可验证化（判⑥的可执行化）

设计期就给 S3/S4 三个机检抓手，不让「遮挡」停留在目检：

1. **标签-几何邻居表**（§I）：每个 HTML 标签登记锚点坐标+几何邻居清单。V2 探针只测标签两两求交，「标签 vs 几何」是盲区——邻居表把盲区变成探针可扩检的输入（S4 按 bbox vs 部件 bbox 求交扩展）。
2. **走廊坐标段**（§I）：流转空中走廊写成 5 点 CatmullRom 控制点表，断言「走廊采样点与三环轨道钢管最近距离 ≥1.2 世界单位」即可机检「不穿轨道」。
3. **billboard 化立法+细节层台阶**（§I）：环上/流转卡一律 billboard（每帧 lookAt 相机，断言 fwd·toCam≈1.00，V2 已有页面内实测先例）；canvas 卡面字=细节层（zoom 3.2× 可读，7px 起），关键值升 HTML 浮签常可读——V2 遗留「F4 命令环卡可辨不可读」按此双手段关闭。
4. **右缘判定协议**：F0/F11 全景「三区+三环全入画」的判定=窗口 1440 − 面板 ~404 ≈ 1024px 有效视口 + 截图裁右缘 1/3 人验（V2 自检协议原文继承，防「全窗宽目检」假 PASS 复发）。

## 4. 配色法定（判②的可执行化）

- **三方色相锁定**：三方主色沿用 DESIGN §3.3 dark 列（驱动 #7c9ff0 / xHC #d9a860 / 设备 #86bd7a），色相族不动；三环 accent 按归属就近取色（命令环=琥珀、事件环=蓝、EP0 环=绿），使「卡从哪来、回执到哪去」的颜色语义与三方一致。
- **承载文字对比度实测制**：凡色对承担「字」的场合（面板/卡面/标签/屏内），写成「前景 on 背景」配对清单，用 WCAG 相对亮度公式脚本实测（本轮 22 对全 ≥4.5:1，脚本 ~/.cache/zcode-tmp/s2_contrast.py，方法可复现）；纯装饰色（灯光/光束本体）不入清单。
- **白底标签路线继承**：HTML 浮签=白底+左色条分级（琥珀=区标/灰=部件/绿=教学锚，V1 修复轮定式），深字 #1c2530 on #ffffff 实测 15.48:1。
- **PBR 参数给区间不给死值**：金属/木纹/塑料给 basecolor hex+metalness/roughness 目标区间，S6 在区间内出贴图、S4 在区间内调参，避免「参数锁死无法做旧」。

## 5. 时序参数化法（判⑤的可执行化）

- **全局系数 k 贯通**：k∈{0.5,1,2}（默认 0.5，宁慢勿快，用户裁定继承）；所有场景动画时长 t=t_base/k，一次乘除贯通到底（V2 main.js tick 先例）。UI 过渡（tab 切换/按钮态）固定墙钟 0.25s 不随 k，防止慢档把界面也拖钝。
- **停留时长修正**：V2 公式 hold=max(1.6, 1.5×speed) 在默认 0.5× 档退化为常数 1.6s——「放慢」诉求只靠整体缩放承担，停留未参与。V3 改为 hold=max(1.2, HOLD_SET/k)，HOLD_SET 默认 2.0s 且在显示 tab 暴露滑杆（1.5–4.0s）：默认档停留 4.0s，比 V2 长 2.5 倍，直接回应意见②。
- **每参数一行成表**：§J 表列参数名/基准值@1×/0.5× 与 2× 换算值/缩放规则/备注，S3 照表写 timeline，不允许散落魔数。
- **特效清单单列**：呼吸灯/翻牌/方波脉冲/光束/闪线/读指针小旗/扳机拉线各给触发工段、波形与时长，作为 S3 动画通道枚举。

## 6. 互动递进可执行性（判⑦⑧的可执行化）

- **每关五要素**：入口/操作/反馈/完成徽章/失败提示——失败提示必须带规范依据文案（pNN），错选不推进（V2 动手台先例）。
- **难度单变量递增**：L1=单点操作（一键正确）；L2=多字段装配但提示在场（高亮+即时纠错）；L3=同链无提示+自由分支（提交后统一判分）+挑战关（排序题）。认知负荷靠「提示在场与否」控制，不靠换题型，保证 L1→L3 是同一技能的加深而非跳跃。
- **解耦立法**：动手台状态机独立于主线工段状态机（V2 X43Lab setRender 钩子形态），操作可借用场景动画通道但互不推进；分支预设是「完整自洽的演示序列」，与动手台判分互不污染。
- **双口径不混写**：主线预设（全速）=规范建议路径（F6 BSR=0→F7 8 字节→F8 Evaluate Context）；「Linux 实路径」预设=独立完整序列（Enable Slot→BSR=1→读 8B→BSR=0）；两者差异只出现在注记卡文字层，同一预设内场景动画只演本路径（S1 §7.2 条 4/5 红线）。

## 7. 自检方案（收尾逐项过）

1. 结构对表：主件 §A–§K 逐节在场且与需求 §3 清单一致。
2. 8 条意见索引表：①–⑧ 每条给出方案落点 § 号与「继承 V2 什么/升级什么」。
3. 验收要点 10 条逐项自检（S2-输出 §3 表）。
4. 避雷扫描：DESIGN §2 逐条对照主件涉及面（命令环唯一/门铃分刻/回执走事件环/BSR 分立/8 字节仅 FS/双操作同成/三 TRB 逐值/EP0 九字段/A0A1/DCBAA 软件装载/伪编号不照抄/PSCEG 跳变/四信号/Disabled 双义）——只引用不复现。
5. 数值溯源抽检：主件中全部规范语义值（字段值/页码/状态名）逐个指回 S1 章节；设计参数抽查标注〔设计参数〕。
6. 语言门：scan_words.py RETIRED_WORDS 全表对四文档扫描，期望非零集={回执}（豁免依据：DESIGN §1.5/§3.2+EVIDENCE 门 4 先例+S1 同口径）；新隐喻词只出现在「待登记」表中并标注词名元引用。
7. 零范围越界：只写 pipeline/ 四文件（ls 对证）。
