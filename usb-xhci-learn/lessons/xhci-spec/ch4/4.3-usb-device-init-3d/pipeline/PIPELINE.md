## 1. 环节闭环（每环节固定五步）
1. worker 写 `S{N}-需求.md`（本环节要什么：输入/输出/验收要点）与 `S{N}-设计.md`（怎么做：方法/结构/自检方案）——**动手实现前落盘**；
2. worker 实现（只写本环节交付物+文档，不动其他环节产物）；
3. worker 写 `S{N}-输出.md`（产出清单/自检对照需求与设计逐项/遗留）；
4. 主会话派 **scorer 子代理**（新鲜上下文、与 worker 无共享记忆）按 §2 判据打分 → `S{N}-评分.md`（分数+逐项评语+PASS/FAIL+分级缺陷清单）；
5. FAIL → 缺陷清单回 worker 自迭代（上限 3 轮；同一缺陷 2 轮修不动→停下如实报告主会话）。PASS → 主会话放行下一环节。

## 2. 评分判据（8 项，每项 10 分制）
①输出文档符合需求文档、设计文档要求 ②颜色搭配美观自然 ③纹理质感细腻 ④场景模型及其变换贴近规范和代码 ⑤场景变换符合人类视觉习惯（移动速度/特效）⑥场景变换关键画面无遮挡 ⑦互动交互易上手通俗易懂 ⑧难易程度形成递进关系。
- **门槛：均分 ≥9 且单项 ≥8.5 = PASS**（用户批准默认值，调整需用户裁定）。
- 适用域：S1 仅 ①④（其余 N/A 不计分）；S2/S3 ①④⑤⑥⑦⑧（②③按设计稿可评则评、无视觉产物则 N/A）；S4–S7 全 8 项。
- scorer 输出格式：通道声明（视觉判语必须实际看图/看场景后给出，禁编造）→ 逐项分数+评语 → 总裁定 → P0（内容/规范错误）/P1（硬伤）/P2（打磨）清单，每条带可执行修复指向。
- scorer 只读不改；worker 自检图=开发工具，判定以 scorer 独立验证为准（V2 教训：施工自检两次口径错位不被采信）。

## 6. 工具通用化纪律（2026-11-10 用户指令，全环节适用）
过程中产生的脚本/工具**尽量通用化，便于复用，避免重复造轮子**：
- **参数化**：机位数/工段表/关卡清单等不写死，从 scene.dsl.json 对应分区读取；路径/文件名走 CLI 参数；
- **归位**：通用工具落 `pipeline/tools/`（头部注释：用途/用法/依赖/消费哪些 DSL 分区）；一次性粘合脚本留 dev/ 并在环节输出文档标注「一次性」；
- **登记**：每环节输出文档附「工具通用化台账」（路径/参数化点/驱动分区/下游复用者）；
- S1–S3 的核验脚本（s3_dsl_check/s2_bbox_check/s2_contrast 等）若形态可复用，由消费环节（S4+）按需收编进 tools/ 并参数化，不重复实现。
