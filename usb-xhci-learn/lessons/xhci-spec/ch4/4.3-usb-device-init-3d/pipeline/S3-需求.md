## 1. 本环节定位

把 S2 场景设计（已过评分门＋修复轮）翻译成**声明式场景数据件** `scene.dsl.json`：S4（Three.js 引擎+适配层）与 S6（Blender 材质工厂）的**共用单源**。DSL 只含数据与显式推导公式，不含过程逻辑；S4/S6 各取所需分区施工。

## 4. DSL schema 硬要求（双消费者约定）

顶层 11 分区：`meta`｜`materials`｜`sceneGraph`｜`rings`｜`cable`｜`corridor`｜`cameras`｜`timeline`｜`interactions`｜`panel`｜`textureRequests`

- **meta**：版本／单位／坐标口径（右手系 Y 上 +X 东 +Z 南）／场景 bbox／速度模型（k 贯通+HOLD 公式+UI 固定值）／camAdapt／**derived**（S2 未给值的集中声明区：推导值+推导式+依据）。
- **materials**：S6 消费段（pbr 材质：basecolor hex／metalness／roughness 区间＋textureRequest 引用）＋S4 侧平色与状态灯语义色（flat）。
- **sceneGraph**：逐实体 id／kind／shape／bbox 或 pos／材质引用／牌文；`labels[]`＝§I.3 的 19 标签锚点（文本逐字／锚点 wu／几何邻居——判⑥探针扩检输入）。
- **rings**：三环公共构造（圆心/半径/槽数/slot 公式/Link 弧/cycle 色对/billboard 立法）＋每环（层高/accent/铭牌/出入槽位/卡型/门铃牌/连接建筑元素）＋连接矩阵（§B.6）。
- **cable**：CatmullRom 控制点／两端插头／方波信号段参数／方向语义表／禁画法红线。
- **corridor**：流转路径控制点＋分段断言口径（§I.1 条 5：起步段豁免/巡航段净空/全程 y 下限/降高门槛）。
- **cameras**：12 工段机位＋三环专属＋走廊取证＋L1 特写＋近景×2 的 pos/tgt/值域/camAdapt 档＋F0 完整性检查单。
- **timeline**：params 注册表（§J.2 全部 36 行）＋F0–F11 工段状态机（动作序列/状态变化/流转卡/hold/物理瞬间/变体）＋F12＋分支预设覆盖图。
- **interactions**：解耦立法＋L1/L2/L3（状态机/选项组/字段值/判据文案/徽章/失败提示）＋quiz。
- **panel**：活指标＋4 tab 内容结构＋窄屏口径。
- **textureRequests**：§F 12 材质逐项（S6 任务书的机器可读形态）。

## 5. 验收要点（8 条）

1. **JSON 可解析**：`python3 -I -m json.tool pipeline/scene.dsl.json` 通过；体积几十 KB 级。
2. **schema 完备**：S2 §A–§K 逐节在 DSL 有落点（S3-输出 给逐节核对表）。
3. **参数零发明**：每个数值字段可指回 S2 § 号（说明文档给溯源列，抽检形态同 S1/S2 评分）；S2 未给而 DSL 必需的参数 → 集中放 `meta.derived`，逐条声明「推导值+推导式+依据」，使用处标注 derived 引用。
4. **引用完整性可机检**：材质/机位/参数/标签/环五类引用全部可解析、实体 id 全局唯一——校验脚本跑通零 FAIL。
5. **标签文案原文**：19 标签文本＋各牌文与 S2 逐字一致（脚本对照），S4 直接渲染、不改写不精简。
6. **双消费者自足**：S6 拿 `materials.pbr`+`textureRequests` 可直接开工（12 材质任务书齐）；S4 拿其余分区零猜测可施工。
7. **纪律**：语言门（scan_words retired，豁免={回执}）跑在说明与输出文档上；隐喻词限已追认名单（DESIGN §3.2＋V2 六词＋S2 十词＋打印机/钢卡座）；中间校验脚本一律 Write 落盘再跑（不用 heredoc/`-c` 多行）；只写 pipeline/ 五文件，不碰 src/。
8. **S2 所有权边界**：S2 评分遗留中属 S2 文本所有权的修订（如 L1 p86 双锚）不在 S3 代改——DSL 以 S2 现行文本为准。
