xHCI 1.2b §4.14 Managing Transfer Rings · p232–251 · §4.14.1 General Scheduling Model p233 / §4.14.2 Periodic Transfer Ring Scheduling p235 / §4.14.3 Interrupt Transfer Ring Scheduling p243 / §4.14.4 Asynchronous Transfer Ring Scheduling p245（页码已机核，见 EVIDENCE.md）

规范要义

本节是 xHC 与传输环打交道的总纲：软件（本页「xHCI 驱动」即规范原文所称 system software（系统软件））把设备端点描述符（含 SuperSpeed Endpoint Companion 描述符）翻译成 Endpoint Context 的 Interval、Max Packet Size、Max Burst Size、Mult 四个字段，xHC 用它们安排 USB 事务；TD 允许把不连续的主机内存缓冲拼成一段连续数据，TD Transfer Size=TD 内全部 TRB 的 Transfer Length 之和，IN 管道可被设备以 Short Packet 截断——xHC 退役该 TD 并推进到下一 TD 或 Enqueue Pointer（Cycle bit 翻转处），先到先算。端点是否被服务由 Pipe Schedule（调度表）决定：Active=在表上、Inactive=不在表上——Running 态端点被写门铃即激活入表，环空或退出 Running 即被摘出，再写一次门铃可重新入表。

调度按 Bus Instance（BI） 组织：一个 BI 代表一份该速度下的单位总线带宽，Total Available Bandwidth 按经验至少比标称速率低 20%，且多个根集线器端口可共享一份 BI（映射对软件不可见）。xHC 每个 BI 典型维护两张 Pipe Schedule——周期表（Isoch+Interrupt）与异步表（Control+Bulk）；每过一遍表，每个端点拿到一个 Service Opportunity（SO）：一块用于搬包的时间，内含 1–3 笔 USB 事务，最多排 MSOPC=(Max Burst Size+1)×(Mult+1) 个 DP。周期管道由 Address Device / Configure Endpoint 命令严格看管，占用不超过 Total Available Bandwidth 的限定百分比（SS/FS 每帧 ≤90%、HS 每微帧 ≤80%，p236），剩下的带宽全归异步管道——异步端点是 Best Effort，投递延迟无上界。系统总线带宽也按同一思路管理：Average TRB Length 是关键指标，系统带宽不足时 Configure Endpoint 同样会被 Bandwidth Error 拒绝（§4.14.1.1 p234）。

三类端点的差异集中在服务时机：Isoch 端点 Active 时 xHC 每 ESIT 恰好处理一枚 Isoch TD（ESIT=2^Interval×125µs，全对齐 MIT 边界），软件挂 TRB 必须领先 xHC 至少 IST（HCSPARAMS2 里的等时调度提前量）；Interrupt 端点把 Interval 当节流/截止参数，每 ESIT 一个 SO、空闲后首笔事务最迟 IST+ESIT 内上总线，TD 可以超过 Max ESIT Payload 而跨多个 ESIT 完成；Bulk/Control 走异步表 round-robin 轮转——多端点时每个 SO 限 MSOPC 个包，只剩一个端点时可连续流。下方机器「调度轮转台」把四小节做成一台可步进的调度机：写门铃入表、微帧节拍取 TD、异步指针轮转点名、环空摘出与重新入表。

原文对照

“An endpoint is considered Active when it is on the xHC’s Pipe Schedule, and Inactive if it is not. Ringing the Doorbell of an endpoint in the Running state will activate it, and the xHC shall place the endpoint in its Pipe Schedule.”

(xHCI 1.2b §4.14 p232)

在表=Active、摘出=Inactive；激活与重新激活都由写门铃触发——门铃是软件驱动调度表的唯一入口。

“An xHC will typically maintain two Pipe Schedules per Bus Instance, one for periodic pipes (Isoch and Interrupt endpoints) and another for async pipes (Control and Bulk).”

(xHCI 1.2b §4.14.1 p233)

每个 BI 一张周期表、一张异步表——三类端点由此分道。

“If an Isoch Endpoint Context is Active, the xHC shall process one Isoch TD from its Transfer Ring each ESIT.”

(xHCI 1.2b §4.14.2.1 p237)

等时调度的节拍器：每 ESIT 恰一枚 Isoch TD；环里没 TD 可取就报 Ring Overrun（IN）/Ring Underrun（OUT）并摘出周期表（p238）。

“The value of this field indicates to system software the minimum distance (in time) that it is required to stay ahead of the host controller while adding TRBs in order to have the host controller process them at the correct time.”

(xHCI 1.2b §4.14.2.1.4 p242)

IST 是软件必须领先 xHC 的最小时间量——不满足会遇到部分成形的 Isoch TD（未定义行为，p242 Note）。

“To ensure fairness across the pipes in the async schedule, the xHC shall schedule Service Opportunities for each Async Pipe using a round-robin algorithm.”

(xHCI 1.2b §4.14.4 p245)

异步侧的公平由规范强制：round-robin 轮转，每过一遍表一个 SO。
