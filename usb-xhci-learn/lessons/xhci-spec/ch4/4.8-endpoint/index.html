规范要义

一个 USB 设备最多支持 31 个端点：15 个 IN、15 个 OUT，外加 1 个 Control；Default Control EP（EP0）是所有 USB 设备都定义的双向端点（p143）。软件（规范原文称 system software（系统软件））要管理这些端点，先要能点名——USB 端点描述符用 4-bit 端点号加方向位编址，xHCI 用同一套骨架：端点号从 16 对 Endpoint Context 里选出一对，方向位再选 IN 或 OUT 那一格（§4.8.1 p144）。每格在 Device Context 里的位置由 Device Context Index（DCI）编号：Slot Context 占 DCI 0，EP0 占 DCI 1，其余按「DCI=(EP Number×2)+Direction」排布（公式原文在 §4.5.1 p83；图4-4 把 0–31 号格画在 p144）。

控制端点是双向的，Direction 位在编址时被忽略——xHC 规定用该对的 IN（奇数）格管理双向端点；EP Number>0 的双向端点，其 OUT（偶数）格被 xHC 忽略（§4.8.1 p144）。初始化时输入端点上下文所有字段（含 Reserved）先清 0，再按端点类型填少数例外：EP0 填 EP Type=Control、按速度的默认 Max Packet Size（设备描述符取回前可先用默认值）、CErr=3、传输环首段地址与 DCS=1（§4.8.2 p144–145）；描述符取回后用 Evaluate Context 命令把实际 Max Packet Size 更新给 xHC（§6.2.3.1 p417——§4.8.2.1 此句原文写作「Evaluate Endpoint Command」，命令本体即 Evaluate Context）。Bulk 的 Max Burst Size 与 Streams 数组、Isoch/Interrupt 的 Mult 与 Max ESIT Payload，各按 §4.8.2.3/§4.8.2.4 的清单填（p145–146）。

端点上下文的现态由 EP State 字段表达，共五态：Disabled / Running / Halted / Error / Stopped（§4.8.3 p146；编码 Table 6-8 p413）。Running 是唯一干活态——Busy（正在跑 TRB）与 Idle（等门铃）只是它的两个子态，传输环跑空也不退出 Running（p148 注）。Halt 条件（STALL、USB Transaction Error 等）把 Running 打进 Halted，Reset Endpoint 命令清断后落到 Stopped；TRB Error 把 Running 打进 Error，Set TR Dequeue Pointer 命令落到 Stopped；Stop Endpoint 命令直接停在 Stopped；门铃一响 Stopped 回 Running。任何态都能被 Disable Slot 打回 Disabled（含 EP0）；去配置（Configure Endpoint DC=1）与 Reset Device 则把除 EP0 外的各态打回 Disabled（p146–148）。EP State 可能滞后——软件应自维护端点状态镜像，不依赖 EP State 的瞬时值（p149）。

判据与旁注：

  • 「enabled」判据：An Endpoint is considered “enabled” if it is not in the Disabled state（p148）——五态里只有 Disabled 不可用（The endpoint is not operational，p413）；门铃禁写与 Endpoint Not Enabled Error（§4.7 p143）都以此为界。
  • Halted/Error 下发 Stop Endpoint：无效果，且回 Command Completion Event，Completion Code=Context State Error（p147）。
  • EP State 会滞后：xHC 应尽量保持及时，但可能让位于高优先级访存——软件应维护内部变量跟踪端点状态（p149）；xHC 复位时非 Disabled 端点的 EP State 值无效（p148）。
  • EP0 三条特例：STALL 任一阶段都进 Halted，Reset Endpoint 清断后门铃（下一个 Setup Stage TD）回 Running（p147 注）；Configure Endpoint 不影响 EP0（p148）；只有 Disable Slot 能把 EP0 从任意态打回 Disabled（p146 注4 / p148）。
  • TRB Error 不保证优雅处理：实现可能未定义行为乃至 HCE——软件的责任是始终呈现格式正确的 TRB（p148 注）。
