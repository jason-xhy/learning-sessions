xHCI 1.2b §4.1 Command Operation · p68

规范要义

xHCI 的管理命令走一条独立通道：软件把命令 TRB 放上命令环，写门铃寄存器 0（DB Target=0）通知 xHC；xHC 执行后，把 Command Completion Event TRB 写进事件环，再用中断（或软件轮询）交还结果。

全规范只有一条命令环——xHC 自身的管理命令与设备槽相关命令（Enable Slot、Address Device……）共用同一条环和同一个门铃入口。命令的参数与回执内容都由 TRB 字段承载，逐条命令的字段在 §4.6 展开（待建）。

三方视角里，命令通道只涉及两方：xHCI 驱动与 xHC 控制器。设备看不到命令——个别命令（如 Address Device）会让 xHC 在总线上代发 USB 请求，那是命令的执行效果，见 §4.3。

原文对照

“There is only one Command Ring that is used for issuing xHCI specific commands or commands related to Device Slots.”
全规范只有一条命令环：xHCI 专用命令与设备槽相关命令共用它。
xHCI 1.2b §4.1 p68
“All xHC commands are issued by placing the desired Command TRB(s) on the Command Ring, then ringing the xHC command Doorbell register, that is, writing the Host Controller Command code to the DB Target field of Doorbell register 0”
命令的完整投递动作 = 命令 TRB 写入命令环 + 写门铃 0（DB Target=0，Host Controller Command）。
xHCI 1.2b §4.1 p68
“All commands result in the generation of a Command Completion Event TRB on the Event Ring.”
每条命令必有一条完成事件回执，回执走事件环。
xHCI 1.2b §4.1 p68
