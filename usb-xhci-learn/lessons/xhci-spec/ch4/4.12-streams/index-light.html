xHCI 1.2b §4.12 Streams · p218–228 · §4.12.1 xHCI Stream Protocol · §4.12.2 Stream ID Management · §4.12.3 Evaluate Next TRB (ENT)（页码已机核，见 EVIDENCE.md）

规范要义

流（Streams）给 SS Bulk 端点扩容传输环：标准端点只配一条 Transfer Ring，开了流的端点最多可挂 65533 条（Stream ID 0、FFFEh=Prime、FFFFh=No Stream 保留——p218 脚注 39）。开流后端点上下文的 TR Dequeue Pointer 改指流上下文数组（Stream Context Array），流 ID（Stream ID）索引进数组，每个流上下文再各持一个 TR Dequeue Pointer 指向自己的传输环。三方分工一句话：xHCI 驱动（本页泳道「xHCI 驱动」即规范原文所称 system software（系统软件））备好各条流的环并写门铃，xHC 按 Stream ID 索引流上下文、推进流协议状态机，哪条流活跃（当前流 CStream）由设备决定。

门铃不是随按随动——xHC 用流协议状态机（xSPSM：Disabled/Idle/Prime Pipe/Start Stream/Move Data，Figure 4-19）配一套去抖动旗标决定每次门铃的效果：IPPV 把 Prime Pipe 压到每进一次 Idle 只发一次；DBPV 补记非 Idle 期的门铃，一回 Idle 立即补发；LFCV 记住设备用 NRDY(Stream n) 流控过当前流，之后不再为它主动搬数；可选的 DSICV 捕获门铃里的流 ID，省一次查环。HID=1 时主机主导的 Idle→Move Data 转移整体关闭——有的用法让设备全权选流更高效；xHC 也可因内部资源限制按 HID=1 运行。

流 ID 管理走层级数组：主流数组 2MaxPStreams+1 项（开辅流时上限 256 项即 MaxPStreams=7；Linear 模式上限 64K 项），Stream ID 拆低位 PSID 与高位 SSID——SSID=0 落主数组直指传输环（SCT=1），非 0 落辅流数组。越界检查是 xHC 的义务：SID=0 或超出数组大小回 Invalid Stream ID Error、SCT 类型不符回 Invalid Stream Type Error，均停端点；Set TR Dequeue Pointer 命令越界则以完成码 TRB Error 报告。设备切流可能落在 TD 中途——xHC 存流状态前先看 ENT 旗标：置位就把后随的 Event Data TRB 执行完再存，免得「数据移完、TD 悬着」把等完成的软件锁死。下方机器「流查表台」把这三小节做成一台可步进的查表机：开流换指针、门铃查表路由、切流再查、存态先查 ENT。

原文对照

“Streams extend the number of Transfer Rings that may be accessible to a SS Bulk USB endpoint. A standard endpoint defines a single Transfer Ring.”

(xHCI 1.2b §4.12 p218)

流把单环端点扩成流数组——上限 65533 条（脚注 39：SID 0、65534=Prime、65535=No Stream 保留）。

“The USB device determines which Stream is active at any time, that is, which Stream Context Transfer Ring is being used to move data.”

(xHCI 1.2b §4.12 p218)

选流权在设备——xHC 只按包头流 ID 备好各条流上下文，活跃的那条叫 CStream。

“Reliably determining whether a Stream Context is active or not, is a Device Class responsibility. There is no xHCI defined method.”

(xHCI 1.2b §4.12 p219)

流上下文是否活跃没有 xHCI 统一判法——空环或带外机制，判定责任归设备类协议（UASP 例见同页）。

“Stream Array bounds checking shall be supported by the xHCI. This feature ensures that an invalid Stream ID presented by a device or a Set TR Dequeue Pointer Command shall not cause the xHC to reference host memory that it doesn’t have access to.”

(xHCI 1.2b §4.12.2.1 p225)

越界检查是 xHCI 的强制义务——坏流 ID 不许变成越权内存访问。

“System software shall set the ENT flag in the last Transfer TRB before a terminating Event Data TRB in a TD. This action ensures the timely execution of an Event Data TRB if the Transfer Ring is flow controlled.”

(xHCI 1.2b §4.12.3 p228)

ENT 用法立法：TD 末尾是 Event Data TRB 时，前一个传输 TRB 必须置 ENT——防流控期 TD 悬挂。

📎 §4.12.1 一条 bulk 管道复用多条流环（p218）

xHCI 1.2b §4.12.1 · p218

Streams allow the data flow of a bulk pipe to be multiplexed between multiple Transfer Rings associated with the endpoint.

流没有另开管道——16 条流环的数据全部走同一条 EP1 OUT bulk 管道，靠包头 Stream ID 区分（数据帧）。

📎 §4.12.2 xHC 按包内 Stream ID 索引流数组（p222）

xHCI 1.2b §4.12.2 · p222

The xHC uses the value of the Stream ID field, received in an Enhanced SuperSpeed Transaction Packet (TP) or Data Packet (DP), as an index into the Stream Context Array(s) to access the Stream Context associated with the packet.

查表路由的规范侧定义：包头的流 ID 进流上下文数组索引——与本节机器读卡滑车同一语义（F4）。

📎 §4.12.2 门铃带 DB Stream ID（p223）

xHCI 1.2b §4.12.2 · p223

A doorbell is rung when work is added to a Transfer Ring. The DB Stream ID indicates the specific Stream of the endpoint that the doorbell ring references.

流端点的门铃一次写两个字段：DB Target=DCI（EP1 OUT=2）＋DB Stream ID（流 1=1）——有工作挂上哪条流环，门铃里说清楚。

📎 §4.12.2.1 越界检查是 xHCI 的义务（p225）

xHCI 1.2b §4.12.2.1 · p225

Stream Array bounds checking shall be supported by the xHCI. This feature ensures that an invalid Stream ID presented by a device or a Set TR Dequeue Pointer Command shall not cause the xHC to reference host memory that it doesn’t have access to.

规范把越界检查定在 xHC 侧（坏流 ID 不得变成越权内存访问，机器 F9）；驱动侧在入队前有同一判据的镜像检查（xhci-ring.c :633）。

📎 §4.12.3 ENT 的软件义务（p228）

xHCI 1.2b §4.12.3 · p228

System software shall set the ENT flag in the last Transfer TRB before a terminating Event Data TRB in a TD. This action ensures the timely execution of an Event Data TRB if the Transfer Ring is flow controlled.

义务的前提是 TD 以 Event Data TRB 结尾——内核此基线不为 bulk TD 排 Event Data TRB、也不置 ENT（TRB_ENT 全树仅 xhci.h 定义与 trace 解码用到）；ENT 语义（存流状态前先评估下一颗 TRB）由本节机器 F7 演进。
