xHCI 1.2b §4.21 PCI Express · p306–307 · PCIe 术语见 PCIe 规范

规范要义

本节是 xHC 与 PCIe 总线的两个交点：配置共享（4.21.1）与 Bus Master Enable（4.21.2）。规范提醒：本节用 PCIe 术语（Physical Layer / Receiver Errors / Data Link / Transaction 层等），错误事件与配置寄存器细节归 PCIe 规范。

关 Bus Master 的正确姿势是一条时序：先把 xHC 停机（R/S=0 并确认 HCH=1），再清 PCI 配置空间的 BME 位。xHC 跑着的时候清 BME，xHC 可能把它当主机控制器错误处理——置 HCE=1 并立即停机，此后恢复要靠 HCRST（内部错误路径，§4.24.1）。

原文对照

“The xHC should be Halted, that is, with the Run/Stop (R/S) bit set to ‘0’, and HCHalted (HCH) verified as being ‘1’ before system software disables bus master activity by clearing the BME bit.”
先停机（R/S=0 + HCH=1 实证）再清 BME——顺序就是防错本身。
xHCI 1.2b §4.21.2 p307
“If the BME bit is set to ‘0’ when the xHC is running, the xHC may treat this as a Host Controller Error, asserting HCE (‘1’) and immediately halt (R/S = ‘0’ and HCH = ‘1’). Recovery from this state will require an HCRST.”
跑着的时候拔总线主控：xHC 可能报 HCE 并当场停机——恢复只能 HCRST。
xHCI 1.2b §4.21.2 p307
“In Virtualization mode, the xHCI is designed to appear as distinct Virtual Functions, where each of the USB devices (Device Slots 0-n) may be mapped exclusively to a specific Virtual Function.”
虚拟化模式下每台设备槽可独占地映射到某个 Virtual Function——设备到功能的映射粒度。

4.21.2 Bus Master Enable：停机时序与错误分支

场景动作序列后果
正常关总线主控R/S=0 → 验证 HCH=1 → 清 BME安全停机
跑着清 BME（xHC 可能判定）HCE=1 → 立即停机（R/S=0 · HCH=1）恢复需 HCRST（§4.24.1 内部错误）

旁注（p306 实现注记，跨 §4.23.2）：FSC 能力位区分挂起流程是否需要对全部端点先发 Stop Endpoint——FSC=1 的实现只对 Running:Busy 端点要求；新实现建议支持 FSC 以兼容假定 FSC 行为的存量驱动。
