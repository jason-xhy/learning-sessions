xHCI 1.2b §4.6 Command Interface · p90–142 · §4.6.1 命令环操作 p91–93 · 命令 17 条（§4.6.2–4.6.18）p93–141

规范要义

命令接口是软件对 xHC 发号施令的唯一正式通道，由 Command Ring Control Register（CRCR）管理：软件（规范原文称 system software，系统软件）把命令 TRB 放上命令环，然后写主机控制器门铃寄存器（门铃 0，DB Target=0）通知 xHC；xHC 取指执行，并把 Command Completion Event 写到主事件环（Primary Event Ring）回报每条命令的完成状态（p90）。命令执行时间由实现定义；多条命令按入环顺序执行（p91 Note）。命令超时没有硬件兜底——完全由软件负责：超时后软件可按 §4.6.1.2 的机制中止命令（p90 Note）。

命令环运行（§4.6.1 p91–93）三件事。①只有一条：每个 xHC 实例只有一条命令环，其上只允许 Table 6-91 定义的 TRB 类型；命令环上的工作项叫 Command Descriptor（CD），一个 CD 恰为一个命令 TRB。②取指指针在 xHC 手里：Command Ring Dequeue Pointer 是 xHC 内部寄存器，不直接暴露给软件，其值经命令完成事件的 Command TRB Pointer 字段回报；初值来自 CRCR 的 Command Ring Pointer 字段（须在 R/S=1 前设好，且只能在 CRR=‘0’ 的停止态修改）。③停与中止：写 CRCR 的 CS 位=‘1’ 停止取指——当前命令执行完后环停，回一个 Completion Code=Command Ring Stopped 的完成事件，此后环上全部命令的所有权交软件（可增删重排），再写门铃即重启（§4.6.1.1 p92）；写 CRCR 的 CA 位=‘1’ 中止当前命令——被中止命令回 Command Aborted 完成事件，随后也有 Command Ring Stopped 事件（§4.6.1.2 p92–93）。实现注记（p93）：通常只有命令「卡住」才会真被中止——典型如 Address Device 在等 USB 设备对 SET_ADDRESS 的应答，那件事不在 xHC 的控制范围内；软件还应给中止操作本身计时，CRR 迟迟不翻转（例如超 5 秒）就该认定 xHC 有更大的问题，动用 HCRST。

§4.6.2–§4.6.18 共 17 条命令，本页总表逐条给出一行。两条用命令的前提纪律（p90 Note）：其一，命令与其引用的全部数据结构必须由软件保证格式正确——xHC 的校验程度因实现而异，收到非法命令的后果是未定义行为；其二，某端点有状态修改命令未决时不得敲该端点的门铃（分组卡尾注列出了两类影响面）。可选规范命令（Force Event / Negotiate Bandwidth / Set LTV / Get Port Bandwidth / Get·Set Extended Property）的支持与否由各自能力位决定，不支持时以 TRB Error 完成码回执。

原文对照

“Software places commands on the Command Ring, then rings the Host Controller Doorbell Register to notify the xHC.”
命令投递两步：放上命令环 → 写门铃通知 xHC——§4.1 命令模型的规范出处。
xHCI 1.2b §4.6 p90
“Software shall be responsible for all command timeouts. If a command times out, software may abort the command using the mechanism described in section 4.6.1.2.”
命令超时全是软件的责任——超时后可按 §4.6.1.2 中止；xHC 侧没有超时兜底。
xHCI 1.2b §4.6 Note p90
“Only one Command Ring exists per xHC instance.”
每个 xHC 实例只有一条命令环——多条命令环是画不得的。
xHCI 1.2b §4.6.1 p91
“The xHC shall generate a Command Completion Event for every command.”
每条命令必有 Command Completion Event——命令与回执一一对应，没有「发出去就算」。
xHCI 1.2b §4.6.1 p91
“The Primary Event Ring receives all Command Completion Events.”
主事件环接收全部命令完成事件——回执走事件环，不回命令环。
xHCI 1.2b §4.6.1 p91
“System software may abort the execution of the current command by writing a ‘1’ to the Command Abort (CA) bit of the Command Ring Control register.”
中止开关=CRCR 的 CA 位写 ‘1’——当前命令回 Command Aborted，环随后停在 Stopped。
xHCI 1.2b §4.6.1.2 p92

§4.6.1 命令环运行四环节：投递 · 回执 · 停止 · 中止

环节开关/载体机制页
投递命令环 + 门铃 0把命令 TRB 写入命令环（Cycle bit=命令环 PCS）→ 写门铃寄存器 0（DB Target=Host Controller Command，DB Stream ID=‘0’）→ xHC 取指执行，直到环停或取空p91
回执主事件环每条命令生成 Command Completion Event：Command TRB Pointer 回指发起命令、Completion Code=完成状态、Slot ID/VF ID 照抄命令 TRB；完成事件按命令在环上的位置有序p91–92
停止CRCR.CS=‘1’当前命令执行完后停止取指，回 Command Ring Stopped；停止期环上命令归软件处置（可删/加/重排），重启=再写门铃（若停机期间改写过 CRCR 指针则从新值起跑）p92
中止CRCR.CA=‘1’当前命令回 Command Aborted 并推进 Dequeue Pointer，随后回 Command Ring Stopped；两命令间隙中止可只有 Stopped 事件；中止后按 §4.6.1.1 重启p92–93

厂商自定义命令（Vendor Defined TRB Type）也走同一模型：同样用 Command Completion Event TRB 报告完成（p92）。
