xHCI 1.2b §4.2 Host Controller Initialization · p68–70（页码已机核，见 EVIDENCE.md）

规范要义

xHCI 驱动（规范原文称 system software，系统软件）把 xHC 当一面寄存器面板来配置：先等 USBSTS 的 CNR 位清零——硬件复位未完成期间写任何 Operational/Runtime 寄存器都被禁止；此后给 CONFIG.MaxSlotsEn 定槽位数、把 DCBAAP 指到设备上下文基地址数组、把 CRCR 指到命令环首 TRB，再把事件环四件（段、ERSTSZ、ERDP、ERSTBA）与中断四件（MSI-X 表、Interval、INTE、IE）装配到位。

中间各步的先后顺序规范不强制（p69 Note），但必须全部在 USBCMD 的 R/S 位置 1 之前完成；R/S=1 之后 xHC 才开始接受门铃引用，根集线器端口也从这时起上报设备连接。

中断是可选件——xHC 可以靠轮询事件环运行（p69 脚注 7，MSI-X 只是本节的示例机制）。端口到 Enabled 态的路径按协议族分叉：USB2（LS/FS/HS）端口必须走端口复位，SS 端口检测到成功 attach 后自动进入 Enabled（p70）。

原文对照

“When the system boots, the host controller is enumerated, assigned a base address for the xHC register space, and the system software sets the Frame Length Adjustment (FLADJ) register to a system-specific value.”

(xHCI 1.2b §4.2 p68)

开机时主机控制器被枚举并分配寄存器基址，驱动把 FLADJ 设为系统特定值——初始化从这里开始。

“After Chip Hardware Reset wait until the Controller Not Ready (CNR) flag in the USBSTS is ‘0’ before writing any xHC Operational or Runtime registers.”

(xHCI 1.2b §4.2 p69)

芯片硬件复位后，必须等 USBSTS 的 CNR 为 0 才能写任何 Operational/Runtime 寄存器——CNR 灯不灭，手不能动。

“Note: This text does not imply a specific order for the following operations, however these operations shall be completed before setting the USBCMD register Run/Stop (R/S) bit to ‘1’.”

(xHCI 1.2b §4.2 p69)

后续各步不隐含特定顺序，但都必须在 USBCMD 的 R/S 位置 1 之前完成——顺序自由，终点唯一。

“Write the USBCMD to turn the host controller ON via setting the Run/Stop (R/S) bit to ‘1’. This operation allows the xHC to begin accepting doorbell references.”

(xHCI 1.2b §4.2 p70)

写 USBCMD 把 R/S 位置 1 打开主机控制器；此后 xHC 才开始接受门铃引用。

“At this point, the host controller is up and running and the Root Hub ports will begin reporting device connects, etc., and system software may begin enumerating devices.”

(xHCI 1.2b §4.2 p70)

至此主机控制器投入运行，根集线器端口开始上报设备连接等事件，驱动可以开始枚举设备（进入 §4.3）。
