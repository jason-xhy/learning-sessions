xHCI 1.2b §4.15 Suspend-Resume · p252–258 · §4.15.1 Port Suspend p253 / §4.15.2 Port Resume p254 · §4.15.2.1 Device Initiated p254 / §4.15.2.2 Host Initiated p255 / §4.15.2.3 Wakeup Events p256（页码已机核，见 EVIDENCE.md）

规范要义

xHC 给每个根集线器端口一套与 USB Hub 等价的挂起/恢复模型（p252）——本页「xHCI 驱动」即规范原文所称 system software（系统软件）。USB3 链路有自己的电源状态阶梯 U0/U1/U2/U3：U0 正常跑包，U3 是端口挂起态，U1/U2 是更浅的低功耗链路态；软件把单个端口置挂起即选择性挂起（Selective Suspend，每个 PORTSC 都支持）。规范把软件发起的恢复称 Resume Events/Actions（恢复事件/动作），总线发起的称 Wake-up Events（唤醒事件）——后者两类来源：远程唤醒设备发 resume 信令/LFPS（xHC 必须响应并按需唤醒系统），连接/拔出/过流（敏感度可用 PORTSC 每端口控制位开关）。挂起整条总线按次序：全部 Enabled 端口选择性挂起 → USBCMD.R/S='0' 关控制器 → 经 PCI PM 降 xHC 功耗态；唤醒后先确认时钟稳定再置 R/S='1'、逐端口写 PLS='0'（p252）。

挂起动作＝写 PORTSC 的 PLS='3'，只许对 Enabled 态端口（PED='1'、PLS<'3'）做，且必须带 LWS='1'（p253–254）。写入与生效之间有时间差：xHC 可立即评估也可等微帧/帧边界（至少每帧一次），立即评估也要等当前事务完成；suspend 信令送达设备之前 PLS 读数不变（最长 10 ms）——软件必须等 U3 转换完成才能把 xHC 放进低功耗态或发起恢复。等法有两难（轮询占处理器、OS 定时器 ~15 ms 太慢），U3 Entry Capability（U3C）解决：PLS 跳到 U3 即置 PLC 出端口状态变化事件（HCCPARAMS2.U3C='1' 时用 CONFIG.U3E='1' 打开；xHCI 1.1/1.2 起 U3C='1' 强制，p254）。挂起前还要用 Stop Endpoint 命令（SP='1'）停掉设备端点（§4.15.1.1 选择性挂起停全部端点；§4.15.1.2 功能挂起按 function 停后再发 SetFeature(FUNCTION_SUSPEND)，p254）。下方机器「端口电源闸台」的主线教学点正在此：写入计数轮与端口状态鼓在信令在途期间读数不同。

恢复分两条路：设备发起（§4.15.2.1）——设备发 resume 信令（USB2）/LFPS（USB3），端口 U3→Resume（PLS='15'）、PLC='1'→端口状态变化事件；软件读 PORTSC 后按协议族收尾——USB3 写 PLS='0' 让 xHC 应答 LFPS 完成握手（xHC 未获指示前不回应 LFPS），USB2 由软件计满 TDRSMDN（≥20 ms，从转 Resume 通知起算）后写 '0'，xHC 检测到信令后 1 ms（TURSM）内反射到全部 Enabled 端口。主机发起（§4.15.2.2）——USB3 直接写 PLS='0'（端口进 U3Exit 子态，xHC 立即发 LFPS）；USB2 写 '15'（xHC 1 ms 内发信令，TDRSMDN 从写 '15' 起算，计满写 '0'）；对 U1/U2 低功耗态端口写 '0' 亦转 U0。两条硬规则：把 Resume 端口转 U0 前必须确认 R/S='1'（保证设备进 U0 时 xHC 能发 ITP 并立即收包，p255 Note）；xHC 从不自动把 Resume/U3 端口拉回 U0（p253 Note）。恢复完成的统一回执：PLS='0'、PLC='1' 再出一次端口状态变化事件（p256）。

原文对照

“System software places individual ports into suspend mode by writing a ‘3’ into the appropriate PORTSC register Port Link State (PLS) field (refer to section 5.4.8).”

(xHCI 1.2b §4.15.1 p253)

挂起动作＝写 PORTSC 的 PLS='3'——前提是端口在 Enabled 态（下一句：should only set PLS='3' when the port is Enabled）。

“Software shall stop all endpoints of a device using the Stop Endpoint Command and setting the Suspend (SP) flag to ‘1’ prior to selectively suspending a device.”

(xHCI 1.2b §4.15.1.1 p254)

选择性挂起前先停端点：Stop Endpoint 命令带 SP='1'；恢复后软件写端点门铃重启（p254）。

“The U3 Entry Capability (U3C) eliminates these delays by asserting PLC when there is a transition of PLS to U3, where the assertion of PLC generates a Port Status Change Event.”

(xHCI 1.2b §4.15.1 p254)

U3C 免轮询免定时器：PLS→U3 即置 PLC 出事件——xHCI 1.1/1.2 起强制（同页 Note）。

“Note that an LFPS Handshake is required for a USB3 U3 wakeup. A device generates LFPS to initiate the resume process.”

(xHCI 1.2b §4.15.2.1 p255，原文 Handshake 后带脚注号 52，引文剔除)

USB3 的 U3 唤醒必须走 LFPS 握手——设备先发 LFPS 发起恢复；xHC 在软件指示前不得回应 LFPS 让握手完成（p255）。

“A U3 to U0 transition of the PLS field shall cause the Port Link State Change (PLC) bit to transition from ‘0’ to ‘1’.”

(xHCI 1.2b §4.15.2.2 p256)

恢复完成的统一回执：PLS 从 U3 变 U0 必置 PLC——PSCEG 0→1 即出端口状态变化事件。

“The xHC shall not automatically transition a root hub port from the Resume or U3 state to the U0 state.”

(xHCI 1.2b §4.15 p253 Note)

Resume/U3 端口回 U0 只能由软件驱动——xHC 没有自动恢复路径（xHC 转 D0 后亦然）。
