xHCI 1.2b §4.19 Root Hub · p272–303 · §4.19.1 Root Hub Port State Machines p272 · §4.19.2 Port Status Change Generation p291 · §4.19.3 Connect Status Change Reporting p294（页码已机核，见 EVIDENCE.md）

规范要义

根集线器（Root Hub）不是一颗真的 hub 芯片：xHC 在内部为「每个物理连接器 × 每种协议」各给一套端口寄存器来模拟 hub 行为——USB2（LS/FS/HS）与 USB3（Enhanced SuperSpeed）两种连接类型的 PORTSC 数量可以不等，由 xHCI Supported Protocol Capability（§7.2）声明归属（§4.19.7 p300）。本页「xHCI 驱动」即规范原文所称 system software（系统软件）。端口状态机的记法是三行一组：状态名 + Port Link State（PLS）+ 信号态，信号态四元组 = PP, CCS, PED, PR（p272）；进入某态时信号态被强制成该态定义值（p272 Note）。两台状态机的初始态都是 Disconnected（p273/p278）；图只示意进出条件，各态的文字定义才是权威（p273 Note）；状态机只引用 PLC 这一个 change bit，其余六个的置位规则归 §4.19.2（p273）。

同一副骨架，两族语义在三处岔开。Disabled 含义不同：USB2 的 Disabled 是连接已检出、等待复位的态（PLS=Polling · 1,1,0,0，Figure 4-25 p273），USB3 的 Disabled 是软件写 PED='1' 得到的链路禁用态（PLS=Disabled · 1,0,0，Figure 4-27 p278）——同名两义，读到 PORTSC 值时先看协议族。Enabled 到达方式不同：USB2 只有端口复位一条路（Disabled→Reset→完成自动迁入，PED/PRC='1'，p274）且复位永不失败（p299 Note）；USB3 在 attach 后由链路训练+配置成功自动迁入 Enabled·U0（p279/p281），其复位（PR/WPR/HCRST）反而可能失败退回 Disconnected（p283）。挂起/恢复路径不同：两族都把 U0 与 U3 作为 Enabled 子态，挂起同写 Wr(PLS=U3+LWS='1')；恢复时 USB2 主机要写两段（先 PLS=Resume、Resume 时长由软件计时，再 PLS=U0），USB3 主机一段写 PLS=U0 走 LFPS 握手，且设备不许拒绝主机的恢复（p290）。电源域是公共底座：Wr(PP='0') 或过流把任一态打进 Powered-off（大泡，p272 原注）。

事件面是本节的另一半。PORTSC 有七个状态变化位——CSC / PEC / WRC / OCC / PRC / PLC / CEC（p291），由硬件或软件条件置位，置位后保持到系统软件写 '1' 清除或 Chip Hardware Reset / HCRST（p291）。每口的变化位 OR 在一起、经 HCHalted（HCH）门控，形成内部信号 PSCEG；PSCEG 的 0→1 跳变才产生 Port Status Change Event——不是「某位=1 就发事件」（p293），且一口的事件在它的全部变化位清零之前被阻塞（PSCEG 回 0 才再开闸，p293 Note）；软件读 PORTSC 与事件环之间没有一致性保证（p292 Note）。attach 上报走三步（§4.19.3 p294）：CCS='1' → CSC='1' → PSCEG 0→1 时投 Port Status Change Event TRB（Port ID 定位端口、Completion Code=Success、Cycle bit=当前生产者态）；驱动解析事件后读该口 PORTSC，用 CSC=1、CCS=1 判出「这是一次插入」。在场判据两族不同：USB2 = PLS 从 RxDetect 迁到 Polling（软件随后必须复位端口才到 U0），USB3 = PLS 从 Polling 迁到 U0（训练成功即在场，p294）。下方机器「根集线器枢纽台」的主线教学点正在此：变化位置位≠事件，读清才再开闸。

原文对照

“Signal State values are: Port Power (PP), Current Connect Status (CCS), Port Enabled/Disabled (PED), and Port Reset (PR)”

(xHCI 1.2b §4.19.1 p272)

信号态四元组 = PP, CCS, PED, PR——状态盒第三行四个数的出处。

“When the Reset operation completes (PR = ‘0’), the port shall automatically advance to the Enabled state, setting PED and PRC to ‘1’.”

(xHCI 1.2b §4.19.1.1.4 p274)

USB2 复位完成自动迁入 Enabled 并置 PED/PRC——USB2 到 Enabled 只此一条路。

“A write to the PORTSC register with the PED field set to ‘1’ shall transition the port, from any state except Powered-off, to the Disabled state.”

(xHCI 1.2b §4.19.1.2.1 p279)

USB3 的 Disabled=软件写 PED='1' 可从（除 Powered-off 外）任一态进入——与 USB2 的 Disabled 完全两义。

“There are seven status change bits in the PORTSC register Connect Status Change (CSC), Port Enabled/Disabled Change (PEC), Warm Port Reset Change (WRC), Over-current Change (OCC), Port Reset Change (PRC), Port Link State Change (PLC), and Port Config Error Change (CEC)”

(xHCI 1.2b §4.19.2 p291)

七个状态变化位的清单原文——机器灯排七盏的出处；PPC 是电源开关能力旗标（p294），不是变化位。

“When set, these bits remain set until cleared by a system software write to the PORTSC register with the appropriate status change bit(s) set to ‘1’, or the assertion of a Chip Hardware Reset or HCRST.”

(xHCI 1.2b §4.19.2 p291)

读清纪律：变化位保持到软件写 '1' 清除（或整机复位/HCRST）——清位闸的出处。

“A port shall generate a Port Status Change Event when there is ‘0’ to ‘1’ transition of the PSCEG signal.”

(xHCI 1.2b §4.19.2 p293)

PSCEG 0→1 跳变才发端口状态变化事件——变化位置位本身不等于发事件。

“For a USB2 Protocol port, “device presence” is indicated by the PORTSC PLS field transitioning from the RxDetect to the Polling state.”

(xHCI 1.2b §4.19.3 p294)

USB2 口「设备在场」= PLS 从 RxDetect 迁到 Polling；软件随后复位端口把它送进 U0。

“For a USB3 Protocol port, “device presence” is indicated by the PORTSC PLS field transitioning from the Polling to the U0 state.”

(xHCI 1.2b §4.19.3 p294)

USB3 口「设备在场」= PLS 从 Polling 迁到 U0——训练成功才算在场，与 USB2 判据不同。
