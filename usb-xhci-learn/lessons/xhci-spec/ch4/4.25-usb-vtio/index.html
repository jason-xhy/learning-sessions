xHCI 1.2b §4.25 USB Virtualization Based Trusted IO Management · p331–334

规范要义

USB VTIO 是可选能力：给 xHCI 定义的各种内存结构与消息建立「多软件/硬件所有者与访问模型」。PCI 形态的 xHC 用 PCI 总线/设备/功能号（BDF）当请求者身份——枚举时锁存的 Primary DMA-ID；VTIO 在它之外再要求一个备用 DMA-ID（全系统唯一、不经标准枚举发现，经 PCI 厂商自定义方法+VTIO 能力寄存器向 OS 披露），用于区分「可信/非可信设备」的内存访问。

VTIO 依赖能按 PCI function 隔离内存访问的基础设施（实现细节不在本规范内；例：Intel VT-d）。硬件隔离的配套纪律：不同 DMA-ID 的内存结构不得共用同一页（按 PAGESIZE 寄存器口径）。注意与 xHCI 扩展能力里的 xHCI-IOV 是两回事——用 xHCI-IOV 就必须关 VTIO；单一 DMA-ID 模式也合法（两个 ID 任选其一独占使用）。

PCI 资源重平衡可能改变分配给 xHC 的 DMA-ID——软件应保证重平衡后先做主机控制器复位，再按需重写 VTIO 分配寄存器。

原文对照

“XHCI VTIO calls for an alternate DMA-ID (in addition to the primary DMA-ID) to be assigned for use by a USB Controller.”
VTIO 的核心动作：在 Primary DMA-ID 之外给 USB 控制器配一个备用 DMA-ID。
xHCI 1.2b §4.25 p331
“The USB VTIO capability should not be confused or conflated with the xHCI-IOV capability defined in the xHCI Extended Capabilities. These are two distinct capabilities meant for different applications. The usage of xHCI-IOV requires that USB VTIO will be disabled.”
VTIO 与 xHCI-IOV 是两种不同能力——用 IOV 就必须关 VTIO。
xHCI 1.2b §4.25 p332
“XHCI SW should guarantee that a Host Controller Reset is issued following such rebalance and re-initialize the VTIO assignment registers as needed.”
DMA-ID 因重平衡而变：先主机控制器复位，再重配 VTIO 分配寄存器。
xHCI 1.2b §4.25.1.1 p333
“To further facilitate hardware isolation SW should ensure that structures in memory corresponding to different DMA-ID’s do not share the same page as defined by the PAGESIZE field in the Page Size Register.”
隔离的页级纪律：不同 DMA-ID 的结构不共用同一页。

VTIO 寄存器定义「硬件访问上述结构时用哪个 DMA-ID」；第 6 章数据结构定义本身零改动（p332）。调试能力（DBC）的内存结构不逐结构分配——整体归入单一控制（p333）。
