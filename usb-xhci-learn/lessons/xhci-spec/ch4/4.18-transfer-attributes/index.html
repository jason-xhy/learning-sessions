xHCI 1.2b §4.18 Transfer Definition and Attributes · p270–272 · Table 4-11 xHC Traffic Attributes

规范要义

本节定义 xHC 发起的 PCIe 事务带哪些请求者属性——No Snoop（NS，不强制缓存一致性嗅探）与 Relaxed Ordering（RO，允许乱序）。前提：PCIe 能力结构的 Enable No Snoop 位已置 1（Table 7-12 位 11，§5.2.8）；即便如此 xHC 也只在能保证地址不在任何缓存里时才许置 NS——不是全部事务都 NS。

软件可以逐 TRB 控制：传输 TRB 的 No Snoop (NS) 标志（Table 4-11 中 IN/OUT 数据行的动态开关）。两类例外不许 NS：MSI 中断的内存写与消息请求（除特别允许处）。Table 4-11 是推荐行为——实现可以自选其它设置。

原文对照

“If Enabled in the PCI Express Capability Structure and directed by software in (for example, TRB No Snoop (NS) flag is set to ‘1’), then the xHC may set the No Snoop bit in the Requester Attributes of PCIe transactions it initiates that do not require hardware enforced cache coherency.”
NS 的三重前提：Enable No Snoop 已置 + 软件经 TRB NS 标志指示 + 事务不需硬件强制缓存一致性。
xHCI 1.2b §4.18.2 p270
“The xHC shall not assert the No Snoop attribute on PCIe transactions for memory requests that are Message Signaled Interrupts, and Message Requests (except where specifically permitted).”
MSI 中断与消息请求不许 NS——中断路径不进这个优化。
xHCI 1.2b §4.18.1 p270
“The Scratchpad Buffer Array and the Scratchpad Buffers that it references are exclusively owned by the xHC.”
scratchpad 归 xHC 独占（§4.20 的「只买单不窥探」在 PCIe 属性上的落点=NS）。

NS 的两个专项（4.18.2.1 / 4.18.2.2）

小节规则页
4.18.2.1 payload 的 NS 选项软件知道「CPU 自上次 xHC 持有后未碰过这缓冲」时可置 IN TRB 的 NS 位——xHC 写该缓冲时走 no-snoop DMA（典型：应用缓冲由 xHC DMA 引擎填过）p271
