整体定位（先挂图）

本课钻进 课 0004 ⑥层 TT 的内部，两个高频错点：缓冲为什么要两个（Q2）与重试决策权在谁（Q3）。两题同源：split 把一次搬运拆成时间上解耦的两段，规则全是围绕这个解耦设计的。

时间解耦：SSPLIT 和 CSPLIT 之间隔着一个真实事务

HS 微帧 125 µs；FS 侧一次满载 64 字节 bulk 事务，光 DATA 字段就要 64×8÷12Mb/s ≈ 43 µs，——整笔再添 token、CRC16、握手与包间隙后约 50–60 µs，单看时长仍装得进一个微帧，但装得进 ≠ 能同微帧闭环：FS 事务的起点是 SSPLIT 在本微帧内交付完的时刻（bulk 的 SSPLIT 吃微帧剩余带宽，位置不保证靠前），完成时刻主机在 HS 侧既看不见也算不准。规范因此要求两者解耦：CSPLIT 绝不与 SSPLIT 同微帧（非周期最早 M+1、共 M+1..M+3 三次机会，附录 A——同微帧 CSPLIT 即错误案例 "CS too early"；周期 interrupt 定死预算微帧之后，§11.18.4③）——于是 SSPLIT（交付）与 CSPLIT（取结果）必然是两个不同微帧里的独立事务——中间夹着 hub ↔ FS 设备的真实异步执行：

规则一 · 缓冲（Q2）：双缓冲乒乓与四种握手语义

§11.17/§11.17.4：每个 TT 的非周期方向（bulk/control）至少 2 个事务缓冲。配套的握手语义表（§11.17.1）——每条都有明确含义：

场景hub 回应err_count
TT 无空间接新 SSPLITNAK（空转但不罚）不增
该端点已有 pending/ready 结果ACK 但忽略数据不增
CSPLIT 到但事务还没跑完NYET（下个微帧再来）不增
CSPLIT 到但找不到匹配缓冲STALL（协议违例）按错误处理

另外每端点任一时刻只允许 1 个缓冲结果（Compare_buffs 规则，§11.17.1）——双缓冲是"在执行＋接新"，不是"堆两个结果"。

规范为什么定"至少 2 个"？只有 1 个会怎样？逐帧推演（无 JS 时全部帧定格可读）：

第 1 帧正常流水：SSPLIT#1 入缓冲 A，FS 事务在执行
微帧 Y0SSPLIT#1 ▸
Y1（等 FS 执行）
Y2（…）
Y3（…）
缓冲 A｜事务#1 在执行：TT 正对下游发 FS 事务
缓冲 B｜空
主机在 Y0 用 SSPLIT 把 bulk 事务高速递进 TT（HS 域里一眨眼）；TT 收下后立刻在下游 FS 总线开跑——64 字节数据光传输就 ≈43 µs，而起点已在本微帧中段（SSPLIT 交付之后），常跨出这个微帧；且无论跨不跨，主机都不在本微帧内问结果——CSPLIT 最早 M+1，这笔活对主机必然落到后续微帧。
第 2 帧交叠时刻：SSPLIT#2 到达，A 未腾空 → 进 B
微帧 Y0SSPLIT#1 ▸
Y1SSPLIT#2 ▸
Y2（…）
Y3（…）
缓冲 A｜事务#1：还没被 CSPLIT 回收
缓冲 B｜事务#2：接新
规范要防的就是这一格：HS 域的节奏不等人——A 还占着，SSPLIT#2 已经到了。请求与应答异步到达、须同时驻留（§11.17）——第二级缓冲就是为这个交叠存在的。
第 3 帧乒乓回收：CSPLIT#1 取走结果，A 即刻腾空
微帧 Y0SSPLIT#1 ▸
Y1SSPLIT#2 ▸
Y2◂ CSPLIT#1
Y3◂ CSPLIT#2
缓冲 A｜已回收——可接 SSPLIT#3
缓冲 B｜事务#2：在执行
CSPLIT 在 Y2 把结果取走，A 马上回到可用状态，正好接下一趟活。两级轮换（乒乓），上游微帧节奏与下游帧节奏互不阻塞——这就是"一个在执行、一个接新"。
第 4 帧反例：若只有 1 个缓冲——NAK 空转与自阻塞
微帧 Y0SSPLIT#1 ▸
Y1SSPLIT#2 ▸ ✗ NAK
Y2◂ CSPLIT#1 SSPLIT#2 重发 ▸
Y3（若仍对撞 → 再 NAK）
缓冲 A｜事务#1 在执行——#2 没有地方放
（第二个缓冲不存在）
TT 无空间只能回 NAK（不罚但空转，§11.17.1）：SSPLIT#2 空跑一趟、下个微帧重发——HS 上游带宽被空转吞掉，下游设备却闲着等活。负载一重，交付时刻反复撞上回收时刻 → 持续 NAK，吞吐塌进"自阻塞"。
第 5 帧为什么恰好 ≥2：下限保"驻留不塌"，上限交给成本
缓冲数后果
1请求与应答应同时驻留做不到 → 第 4 帧的空转/自阻塞
≥2（规范下限，§11.17.4）恰好覆盖"一个在执行＋一个接新"的异步两层
更多厂商可选的性能余量（§11.19 只给空间公式不强制）——只影响成本，不影响正确性
闸门仍在：每端点任一时刻只许 1 个结果缓冲（Compare_buffs，§11.17.1）——双缓冲是流水位，不是备份位。一句小结：双缓冲是流水线的最小深度，不是冗余备份。

规则二 · 重试决策权（Q3）：三层对照，按职责边界分工

TT 本地（FS handler）——只限非周期的事务错误：bulk/control 在 FS 域遭遇传输错误（bit 错/超时）可本地重试，3 次后以 stall 状态回报；但对 ACK/NAK/STALL 等握手结果不得重试（§11.17.2）。 
/* 摘要库 §11.17.2 引文 */
"If the transaction experiences a transaction error three times,
 the full-/low-speed handler will reflect this as a stall status result"
↓
主机侧——three strikes 与 halt：err_count < 3 主机重试；≥ 3 做端点 halt；halt 之后软件发 Clear_TT_Buffer 清 TT 的 busy 缓冲（§11.17.1/§11.17.5）——这正是 hub_clear_tt_buffer（hub.c:816-831）存在的理由，课 0004 的内核锚点在这里接上规范。 
/* 摘要库 §11.17.1 引文 */
"it increments an error count (err_count) and, if the count is less
 than three..., it will retry the transaction. If the err_count is
 greater or equal to three..., the host controller does endpoint
 halt processing"
↓
periodic（interrupt/iso）——TT 完全不本地重试：§11.20.1（interrupt）与 §11.21（iso）明文。因为 interrupt 活在主机的微帧管道里（§11.18.4：SSPLIT/CSPLIT 在哪个微帧都排得死死的），NAK 不是错误而是"没就绪"的合法状态（§5.3.2），hub 若自作主张重试会（a）吃掉 187.5 字节/微帧的 FS 预算（b）打乱主机按 bInterval 的服务记录（c）重复执行风险。结果如实经 CSPLIT 回报（iso OUT 例外：根本没有 CSPLIT，§11.21），处置权在主机且语义分岔——interrupt 按服务节奏重新轮询；iso 无握手无重试（§5.6.5），坏周期直接放弃、下一周期传新数据；periodic 的 CSPLIT 遇传输错误也是主机侧"立即重试"（§11.18.4⑥），不是 TT 的活。

重试决策权的规范依据，同样逐帧推演——先看约定，再推演"假如 TT 自作主张重试"会闯什么祸（§11.17.2/§11.20）：

第 1 帧约定：排班权在主机，TT 只是执行者
主机排的周期预算端点X interrupt
同一 FS 帧预算端点Y iso
同一 FS 帧预算端点Z interrupt
…（§11.18.4 微帧管道）
periodic 传输活在主机的微帧管道里：哪个微帧发 SSPLIT、哪个微帧收 CSPLIT、下游 FS 时间分给谁，全是主机排好的（FS 侧每微帧 187.5 raw 字节的预算记录，§11.18.1）。TT 的职责边界：照单执行、如实回报。
第 2 帧设备 NAK：不是错误，是"没就绪"
微帧 MSSPLIT(IN) ▸
FS 侧IN → 设备 → NAK
微帧 M+2◂ CSPLIT 报 NAK
interrupt IN，设备还没备好数据，回 NAK——§5.3.2 里这是握手不是错误。TT 把 NAK 原样经 CSPLIT 交回主机："何时再试"的决策立刻回到排班者手里。
第 3 帧反例推演：假如 TT 自作主张重试
FS 下游IN → NAK（排班内的那次）
私自 +1IN → NAK
私自 +2IN → NAK
被挤的邻居端点Y iso 时隙 ✗
设想一个"好心"的 TT 在下游马上再发一次 IN，又 NAK，再发……下游 FS 时间是主机已经分给别人的预算——私自重试吃掉的每一微秒，都是从同 hub 下其它端点嘴里抢的。
第 4 帧不这样设计的四个代价
  • 带宽超支：挤占别的端点的预留时隙——iso 无重传（§5.6.5），被挤＝直接丢数据；
  • 记录失真：主机按 bInterval 记录"本周期是否已服务"，TT 私自多跑打乱服务节奏；
  • 重复执行：设备恰好在某次私自重试时备好 → 同一逻辑请求被执行两次；
  • 谎报成功：重试碰巧成功，主机看到"成功"却不知失败发生过——错误统计与恢复决策全部失真。
四条合起来就是 §11.20 的约定理由：periodic 的结果（含失败）必须如实上报（iso OUT 无 CSPLIT、无从上报，§11.21），处置由主机按服务语义分岔——interrupt 按服务节奏重新轮询；iso 素来无握手无重试（§5.6.5），该周期即放弃；CSPLIT 自身遇传输错误也是主机侧立即重试（§11.18.4⑥），仍不是 TT 的活。
第 5 帧对照小结：非周期为什么反而允许 TT 重试
bulk/control（非周期）interrupt/iso（periodic）
吃的带宽剩余带宽（best-effort），不占排班预算预算管道里的每一笔都占用其他端点的预算
TT 重试允许，3 次封顶后以 stall 如实回报（§11.17.2）一个都不许（§11.20.1/§11.21）
非周期允许 TT 吸收 FS 域的瞬时 bit 错，是因为重试不破坏任何一方的约定（要么成功要么 stall，结果如实上报）；periodic 不允许，是因为每次重试都在花别人的预算。一句话：重试决策权跟着调度权走。
两道错题的小结：Q2——解耦需要排队，双缓冲=一个在执行一个接新；Q3——重试决策权跟着调度权走：非周期事务错误归 TT（3 次封顶），握手结果与全部 periodic 归主机——interrupt＝主机按服务节奏再试，iso＝永不重试、当期放弃（§5.6.5）。
