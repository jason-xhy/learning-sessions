整体定位（先挂图）

本课在整体地图（课 0001）的 ⑥ hub 层——USB2 特有的核心机制；并承接 课 0003 的"硬件吸收"叙事：xHCI 时代 split 的执行被吸进控制器硬件，usbcore 里只剩错误恢复。

为什么需要 TT：一个 hub，两个时钟域

高速 hub 的上行口跑 HS 域：480 Mb/s、微帧 125 µs；下行口可能挂 FS 设备：**12 Mb/s、帧 1 ms**（§7.1.11/§7.1.12）。两种信令、两个节拍，hub 里的事务翻译器（Transaction Translator，TT）负责两边互译。规范的做法非常克制：

split 只存在于主机控制器 ↔ hub 之间，设备永远不可见（§5.10、§11.1.1）。hub↔设备一侧仍是普通 FS/LS 事务。设备无需知道任何事——这就是兼容性的代价全由主机侧承担的设计。

数字直觉：一个 HS 微帧（125 µs）只占 FS 帧（1 ms）的 1/8——翻译的实时性压力全压在 hub 的 TT 缓冲与调度上。

/* hub.c:816-831 */
/* USB 2.0 spec Section 11.24.2.3 */
static inline int
hub_clear_tt_buffer(struct usb_device *hdev, u16 devinfo, u16 tt)
{
        /* Need to clear both directions for control ep */
        if (((devinfo >> 11) & USB_ENDPOINT_XFERTYPE_MASK) ==
                        USB_ENDPOINT_XFER_CONTROL) {
                int status = usb_control_msg(hdev, usb_sndctrlpipe(hdev, 0),
                                HUB_CLEAR_TT_BUFFER, USB_RT_PORT,
                                devinfo ^ 0x8000, tt, NULL, 0, 1000);
                if (status)
                        return status;
        }
        return usb_control_msg(hdev, usb_sndctrlpipe(hdev, 0),
                        HUB_CLEAR_TT_BUFFER, USB_RT_PORT, devinfo,
                        tt, NULL, 0, 1000);
}

评审视角

  • TT 类补丁分两族：xHCI 内部的 split 调度（对表 §11.16-11.23 + 上下文构造字段）与 usbcore 的 ClearTTBuffer 恢复路径（对表 §11.24.2.3）。两族锚点不同，别混审。
  • 数字复核清单：微帧 125 µs / FS 帧 1 ms（§7.1.12）、每微帧 187.5 raw 字节（§11.18.1）、每方向 ≥2 缓冲（§11.17）、interrupt 禁止本地重试（§11.20）。
