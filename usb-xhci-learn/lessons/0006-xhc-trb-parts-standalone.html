TRB 是什么 · 16 字节里装了哪些信息

TRB 全称 Transfer Request Block，中文通行译名传输请求块（本课行文沿用缩写 TRB）——16 字节一颗，是环上可被硬件直接读取的最小指令单位。它的设计要点只有一条：槽里放的是描述，不是数据。搬什么、搬到哪、搬多少，全部写成字段；真正的字节留在 DMA 缓冲区里，由 xHC 按字段里的地址去取。xHCI 把这套分工摊在 DW0-DW3 四个 32 位字上：

要表达的信息TRB 里的位置说明
数据在哪（缓冲区起始地址）DW0-164 位 DMA 地址，由软件填写；Setup TRB 例外，见下节 IDT
搬多少DW2 bit16-0（Transfer Length）单颗 ≤64K；bit21-17 的 TD Size 记录本 TD 剩余包数
完成后通知谁DW2 bit31-22（Interrupter Target）＋DW3 的 IOC/ISP事件路由到哪个中断器、什么条件下产生事件
这颗 TRB 此刻归谁DW3 bit0（cycle）轮次匹配即归 xHC，是 0007 全课的主线
与相邻 TRB 是否同属一次传输DW3 bit4（chain）非尾颗置 1、尾颗清 0，TD 的边界就写在尾颗上
这是什么种类的 TRBDW3 bit15-10（TRB Type）Normal / Setup / Data / Status / Link / Event…

有两处容易想当然，先点明。第一，数据永远不进槽：即便搬 64KB，槽里也只有地址与长度；唯一例外是控制传输的 8 字节 setup 包，用 IDT 位把值直接内联进 DW0-1（下一节展开）。第二，TRB 是一次性的：xHC 消费完既不擦除也不回收，槽里的旧字段要等下一圈被覆盖——旧值凭什么不会被误当成本圈的新指令？靠 cycle 位的轮次比对（0007 第 1 章）。表里"归谁"那一行之所以单列，原因也在这里。

把 16 字节看透 · DW0/DW1 的四种身份（DW2/DW3 一并收齐）

一颗 TRB ＝ 16 字节 ＝ 4 个 32 位字（§4.11.1）。§6.4（p465 起："The Transfer Request Block is the basic building block"）把它约定成三段：DW0＋DW1 合成一个 64 位"参数字段"、DW2 状态字、DW3 控制字。xHCI 的一个关键设计随即登场：参数字段的含义随 TRB 类型改变——同一对 DW0/DW1，四种身份。顺带把 §4.11.1.1（p208-209）的分工约定记下：传输/命令 TRB 由软件清零后填写（软件生产）；事件 TRB 由 xHC 填写（"the consumer is system software and the producer is the xHC"）。

身份一 · Normal/Data TRB——64 位数据缓冲指针（Table 6-20，p466："Offset 00h and 04h – Normal TRB Field Definitions"）。"数据在哪"：主存里那段数据的起始 DMA 地址，DW0 低 32 位、DW1 高 32 位。两条硬约束（专题一的 64K 切分法即源于此）：单颗 ≤64K（TRB_MAX_BUFF_SIZE，xhci.h:1266-1267）、缓冲段不得跨 64K 边界（TRB_BUFF_LEN_UP_TO_BOUNDARY，:1269-1270）。

身份二 · Setup Stage TRB——8 字节 setup 包本体（§6.4.1.2.1，Table 6-23/6-24，p468）。控制传输的数据恰好只有 8 字节——与其写个指针让 xHC 再跑一趟主存，不如把值直接写进参数字段：IDT 位（Immediate Data，DW3 bit6）声明"指针字段装的是立即数据"，上限恰 8 字节（TRB_IDT_MAX_SIZE，xhci.h:1059）。这就是"数据不进槽"的唯一例外。驱动怎么拼这两个字？内核的拼装现场（IDT 先打在控制字上，再逐字段压进 field1/field2）：

身份三 · Link TRB——下一环段首槽的 64 位指针（§4.11.5）。环回绕点上的指向标记："下一颗在哪"。它为什么只能住段末槽、四个字段各管什么——零件节与专题二细看。

身份四 · Transfer Event——已完成的那颗传输 TRB 的指针（§6.4.2.1，Table 6-37/6-38，p477-478）。两个方向互为镜像：生产方向的 TRB 用 DW0-1 写"数据在哪"；回报路径的事件用 DW0-1 写"哪颗 TRB 完成了"。事件结构体的内核注释点明身份，handle_tx_event 的开头四连读则把整颗事件拆干净——收件人（slot/EP）自带在 DW3、完成码（CC）在 DW2 高 8 位、回指地址（TRB 指针）在 DW0-1：

先认零件 · 槽 / TRB / TD / Link / 回绕点——一套度量量到底

本课两个专题与 0007 的全部动画都由这五个词组合而成，先把零件列出来（从字节到环，四级嵌套）：一颗 TRB = 16 字节 = 4 个 32 位字（§4.11.1）；槽 = 环上一颗 TRB 的位置——所以一个槽恰好 16 字节，槽里永远住着一颗 TRB（数据 TRB 或 Link TRB）；TD = 一次传输 = 1..N 颗 TRB 用 chain 位串成的一列——TD 与槽的关系就是"占用"：130KB bulk OUT 先把数据切成 64K+64K+2K 三段，每段配一颗 16 字节 TRB（DW0-1 填缓冲段地址、DW2 填长度，数据本身不进槽），三颗 TRB 共占 3 个槽＝48 字节；一次 8 字节控制请求的 Setup+Data+Status 同样占 3 个槽。槽恒为 16 字节，"64K"只是 TRB 里写的长度——TD 占几个槽，完全由传输长度与切分规则决定；段 = 256 槽 × 16B = 4096 字节恰一页（前 255 槽住数据、第 256 槽固定住 Link TRB，xhci.h:1260-1267）；环 = 段链接成的圆（可多段、可扩容，专题二）。最后是回绕点：环在内存里是一段段直线，逻辑上才弯成圆——段走完时从末槽跳回首槽，这个跳转点就是回绕点。末槽住不得数据 TRB（xHC 扫到会把它的内容当指令执行），所以固定放一颗 Link TRB 当"回到开头"的指向标记：

📎 §4.9 TRB 恒 16 字节（p168）

xHCI 1.2（2019） · p168

All TRB data structures shall be 16 bytes in size.

槽=16B 的规范出处；DW0-3 四写恰好一颗。

📎 Table 6-21 单颗 TRB 长度上限 64K（p466）

For an OUT, this field defines the number of data bytes the xHC shall send during the execution of this TRB. … Valid values are 0 to 64K.

📎 §4.11.2.1 Normal TRB 服务 bulk/interrupt（p211）

xHCI 1.2（2019） · p211

📎 §4.11.2.1 chain 位＝多颗捆一件（p211）

xHCI 1.2（2019） · p211

The Chain bit (CH field in Figure 6-8) may be set to '1' in Normal, Data Stage, Status Stage, and Isoch TRBs to form multi-TRB Transfer Descriptors. Chaining allows scatter/gather operations.

chain 是四种传输 TRB 共用的捆绑标记——TD 的边界写在尾颗 chain=0。

📎 §4.9 环不跨 64K 边界（p168）

xHCI 1.2（2019） · p168

📎 §4.10 IOC 命中即产事件（p189）

xHCI 1.2（2019） · p189

If upon transfer completion of a TRB the Interrupt On Completion (IOC) flag is set, the xHC shall generate a Transfer Event TRB. Note the generation of an Event TRB always generates an interrupt to the host.

尾颗 TRB 打 IOC=整件 TD 完成即中断——事件按「件」发一颗的规范依据。

全景图②步说"urb 被改写成 TRB 链"——现在把这套装配流程展开（六步完整流程在 0007）。urb 是 usbcore 与 hcd 之间的约定（缓冲地址/长度/回调），TRB 是驱动与 xHC 之间的约定（16 字节定长指令，§4.11.1）。两者粒度差两个数量级，中间隔两层换算：urb 先切成若干 TD（Transfer Descriptor，§4.9.1：xHC 调度与完成事件的最小单位），每个 TD 再切成一串 TRB（CHAIN 位相连，§4.11.7 TD Usage Rules）。urb 切几个 TD，全部规则只有三条（bulk OUT 那条的"补零包"：以零长包收尾一条 bulk OUT 是设备侧的普遍期待，内核为此允许"数据 TD＋零包 TD"两段）：

chain 这个控制位单独演示一遍——三帧只看捆绑标记（cycle 全部假设恰好匹配）：

第 1 帧130KB 来了：一颗 TRB 装不下，先切三段数据

本帧只看"切"这个动作：一颗 TRB 的 DW0-1 只装得下一个 ≤64K 且不跨边界的缓冲段，130KB 只好切成三颗。但切完只是三段数据，还不是一个 TD——把数据打成一件的，是下一帧的 chain。

第 2 帧chain＝捆绑标记：尾 TRB 收尾（chain=0）＋完成中断（IOC）

本帧只看链的两端：中间 TRB 的 chain=1 声明"下一槽与我同属一传"；尾 TRB chain=0＝收尾，再搭 IOC 位＝整件的完成中断（§4.11.7）。chain 决定"几颗 TRB 算一件"——这就是槽与 TD 的全部关系：槽是环上的位置，chain 把若干位置上的 TRB 串成一次传输。

第 3 帧xHC 视角：取走链头＝取走整件，事件按"件"发一颗

本帧只看"一口气"：xHC 校验过链头后，沿 chain 一直走到 chain=0 为止——整条链是一个调度与完成单位，事件只发一颗。补充一个预告：TD 中途跨过回绕点时，这个回绕点上的 Link TRB 会被改写 chain 位把链续上（0007 第 3 章联动动画第 5 帧细看那个场景）。

专题二 · ring 的几何：segment × 256 槽 × Link TRB × 扩容

三层语法解决了"TD 切成几颗、怎么捆"——还差环的骨架（cycle 轮次的完整约定与事件环 ERST 的分野是 0007 的两个专题）：多段 segment 怎么拼成环、写满了怎么办。先记三个常数（TRB 16 字节 × 256 = 4096 = 一页，DMA 对齐友好，xhci-mem.c:2440-2448）：

/* xhci.h:1260-1267 */
#define TRBS_PER_SEGMENT	256
/* Allow two commands + a link TRB, along with any reserved command TRBs */
#define MAX_RSVD_CMD_TRBS	(TRBS_PER_SEGMENT - 3)
#define TRB_SEGMENT_SIZE	(TRBS_PER_SEGMENT*16)
#define TRB_SEGMENT_SHIFT	(ilog2(TRB_SEGMENT_SIZE))
/* TRB buffer pointers can't cross 64KB boundaries */
#define TRB_MAX_BUFF_SHIFT		16
#define TRB_MAX_BUFF_SIZE	(1 << TRB_MAX_BUFF_SHIFT)

每段前 255 槽放数据 TRB，第 256 槽固定是 Link TRB（段有效容量 = 段数 × 255，:361）。Link TRB 的内容由初始化写死：类型改写为 TRB_LINK，Buffer Pointer = 下一段首槽的 DMA 地址（xhci-mem.c:97-114）。而 Link TRB 控制字的 Toggle Cycle 位（TC＝DW3 bit1 在 Link TRB 上的身份，xhci.h:958）有一个关键细节——TC 只挂在"整个环最后一段"的 Link TRB 上，中间段的 Link 只跳转、不翻轮次（§4.9.2.1）：多段环转一整圈，cycle_state 只翻一次：

/* xhci-mem.c:105-114（xhci_set_link_trb）段尾 TRB 改写成跳转指令 */
	trb = &seg->trbs[TRBS_PER_SEGMENT - 1];

	/* Set the last TRB in the segment to have a TRB type ID of Link TRB */
	val = le32_to_cpu(trb->link.control);
	val &= ~TRB_TYPE_BITMASK;
	val |= TRB_TYPE(TRB_LINK);
	if (chain_links)
		val |= TRB_CHAIN;
	trb->link.control = cpu_to_le32(val);
	trb->link.segment_ptr = cpu_to_le64(seg->next->dma);
/* xhci-mem.c:129-130 Toggle Cycle 只挂最后一段（§4.9.2.1/§6.4.4.1） */
	/* See section 4.9.2.1 and 6.4.4.1 */
	ring->last_seg->trbs[TRBS_PER_SEGMENT - 1].link.control |= cpu_to_le32(LINK_TOGGLE);

环满了怎么办？——动态扩容（这是传输环区别于命令环/事件环的第三种答案）。prepare_ring（:3268）在每次排队前算空间：enqueue 前方余量不足就调 xhci_ring_expansion（xhci-mem.c:413）再插新段；命令环禁扩（CRCR 指针由硬件持有，软件无权改写它的几何）：

/* xhci-ring.c:3302-3316（prepare_ring） */

		new_segs = xhci_ring_expansion_needed(xhci, ep_ring, num_trbs);

		xhci_err(xhci, "Do not support expand command ring\n");

	if (new_segs) {
		xhci_dbg_trace(xhci, trace_xhci_dbg_ring_expansion,
				"ERROR no room on ep ring, try ring expansion");
		if (xhci_ring_expansion(xhci, ep_ring, new_segs, mem_flags)) {
			xhci_err(xhci, "Ring expansion failed\n");

扩容的插法很讲究：新段splice 进 enqueue 所在段之后（不是接在队尾），并保持一条不变量——全环有且只有一个带 TC 的 Link TRB，永远在 last_seg 段尾。新段先按独立小环初始化（新末段带 TC，:429 经 xhci_initialize_ring_segments），拼接后若插入点就是旧末段，就把旧末段的 TC 撤掉、last_seg 指针移交给新末段（xhci-mem.c:169-177）：

	dst->enq_seg->next = src->first_seg;
	if (dst->type != TYPE_EVENT) {
		chain_links = xhci_link_chain_quirk(xhci, dst->type);
		xhci_set_link_trb(dst->enq_seg, chain_links);

一句话小结：ring = 段链表；段 = 255 数据槽 + 1 Link 槽；Link 携带下段地址，TC 只在 last_seg 段尾出现（唯一轮次翻转点）；传输环可按需 splice 扩段，命令环禁扩，事件环几何外置 ERST。cycle 约定（0007 第 1 章）与 ERST 对照（0007 第 2 章）补上后，三种环的静态几何与动态行为就全部闭环。

toggle cycle（TC）这个控制位单独演示一遍——三帧只看"轮次什么时候翻"。前置一句就够：每颗 TRB 的 DW3 bit0 是 cycle（所有权标记），软件与 xHC 各记一个"当前轮次"，绕环整整一圈后轮次取反——完整约定在 0007 第 1 章，这里只看翻轮次的记录（示意把每段缩成 4+1 槽，真实 255+1）：

第 1 帧两段环＝两个回绕点，只有最后一段的回绕点带 TC

本帧只看两颗 Link 的差别：多段环里每段末尾都有一颗 Link（负责段与段拼接），但TC 只挂在整环最后一段——中间段的回绕点是纯跳转，不翻轮次。

第 2 帧转一圈：跨两个回绕点，轮次只翻一次

本帧只看轮次盒：跨中间回绕点①什么都不发生（纯跳转），跨末段回绕点②轮次才翻。生产/消费两侧各翻各的——软件在 inc_enq_past_link（:254-260），xHC 在跨过回绕点取指时——两侧从不同步全局状态，只在各自的回绕点上翻各自的轮次。

第 3 帧反例：若两个回绕点都带 TC——翻两次＝空翻

本帧只看"为什么不能两颗都带 TC"：翻两次等于空翻——轮次回到原值后，上一圈旧值残留的 cyc 恰与轮次相同，会被当成新数据（误判为有效）。所以规范把翻轮次的权力收归整环唯一的回绕点。
