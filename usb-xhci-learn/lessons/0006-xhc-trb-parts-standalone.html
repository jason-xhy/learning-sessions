提单是什么 · 先讲货运，再讲 TRB

本课把 TRB 叫"提单"——这个词的来路要先讲清。提单（bill of lading）是海运沿用几百年的单据：托运人（货主）把货交给承运人（船公司）时，由承运方签发，单上写明——托运人是谁、收货人是谁、货物名称与件数重量、装哪条船哪个航次、货存在哪个仓位，以及最关键的一条法律属性：凭单提货——收货人不进堆场翻找，只认单交货。对工程视角来说，提单的要点只有一个：单上不装货。货在舱里，单是"关于货的描述与指令"；承运人照单运输、照单交付、照单通知。xHCI 的世界几乎逐条对得上：

三个不像，防止过度类比：① 方向反了——现实提单由承运人签发、托运人持有；TRB 由托运人（软件）写、承运人（xHC）读，"生效签章"（cycle 位）握在生产者手里。② 现实提单是物权凭证、可背书转让、长期存档；TRB 是主存里的一次性消费品——消费后成"残影"，下一圈被直接覆写，谁也不留底（0007 第 1 章的看点）。③ 现实提单描述货、不装货；TRB 有一个精心设计的例外——货小到 8 字节以内时，直接把货抄在单上（IDT 立即数据，恰是下一节的入口）。比喻用到"单上不装货、只写货的描述与指令"这一层为止。

把 16 字节看透 · DW0/DW1 的四种身份（DW2/DW3 一并收齐）

一颗 TRB ＝ 16 字节 ＝ 4 个 32 位字（§4.11.1）。§6.4（p465 起："The Transfer Request Block is the basic building block"）把它立法成三段：DW0＋DW1 合成一个 64 位"参数字段"、DW2 状态字、DW3 控制字。xHCI 的一个关键设计随即登场：参数字段的含义随 TRB 类型换装——同一对格子，四种身份。顺带把 §4.11.1.1（p208-209）的分工立法记下：传输/命令 TRB 由软件清零后填写（软件生产）；事件 TRB 由 xHC 填写（"the consumer is system software and the producer is the xHC"）。

身份一 · Normal/Data TRB——64 位数据缓冲指针（Table 6-20，p466："Offset 00h and 04h – Normal TRB Field Definitions"）。"货在哪"：主存里那段数据的起始 DMA 地址，DW0 低 32 位、DW1 高 32 位。两条硬约束（钻点一的 64K 切分法即源于此）：单颗 ≤64K（TRB_MAX_BUFF_SIZE，xhci.h:1266-1267）、缓冲段不得跨 64K 边界（TRB_BUFF_LEN_UP_TO_BOUNDARY，:1269-1270）。

身份二 · Setup Stage TRB——8 字节 setup 包本体（§6.4.1.2.1，Table 6-23/6-24，p468）。控制传输的"货"恰好只有 8 字节——与其写个指针让 xHC 再跑一趟主存，不如把货直接抄在单上：IDT 位（Immediate Data，DW3 bit6）声明"指针字段装的是立即数据"，上限恰 8 字节（TRB_IDT_MAX_SIZE，xhci.h:1059）。这就是提单比喻的例外条款。驱动怎么拼这两个字？内核的拼装现场（IDT 先打在控制字上，再逐字段压进 field1/field2）：

身份三 · Link TRB——下一环段首槽的 64 位指针（§4.11.5）。环的接缝路标："下一站在哪"。它为什么只能住段末槽、四件行李各管什么——零件节与钻点二细看。

身份四 · Transfer Event（回执）——完成的传输 TRB 的指针（§6.4.2.1，Table 6-37/6-38，p477-478）。对称的漂亮设计：生产方向的提单 DW0-1 写"货在哪"；回程方向的回执 DW0-1 写"哪张单完成了"。事件结构体的内核注释一句话点破身份，handle_tx_event 的开头四连读则把整颗回执拆干净——收件人（slot/EP）自带在 DW3、判决码（CC）在 DW2 高 8 位、"单号"（TRB 指针）在 DW0-1：

/* xhci.h:809-815 事件 TRB 结构——DW0-1 的身份由注释一句话点破 */

先认零件 · 槽 / TRB / TD / Link / 接缝——一把尺子量到底

本课两个钻点与 0007 的全部动画都在这五个词上搭积木，先把零件摆上桌（从字节到环，四级嵌套）：一颗 TRB = 16 字节 = 4 个 32 位字（§4.11.1）；槽 = 环上一颗 TRB 的车位——所以一个槽恰好 16 字节，槽里永远住着一颗 TRB（数据 TRB 或 Link TRB）；TD = 一次传输 = 1..N 颗 TRB 用 chain 位捆成的一列——TD 与槽的关系就是"占用"：130KB bulk OUT 先把数据切成 64K+64K+2K 三段，每段配一颗 16 字节 TRB 当提单（货运比喻：单上只写"货在哪、有多少"，货本身不在单上——对应 DW0-1 填缓冲段地址、DW2 填货量，数据永远不进槽），三颗提单共占 3 个槽＝48 字节；一次 8 字节控制请求的 Setup+Data+Status 同样占 3 个槽。槽恒为 16 字节，"64K"只是提单上写的货量——TD 占几个槽，完全由传输长度与切分规则决定；段 = 256 槽 × 16B = 4096 字节恰一页（前 255 槽住数据、第 256 槽固定住 Link TRB，xhci.h:1260-1267）；环 = 段链接成的圆（可多段、可扩容，钻点二）。最后是接缝：环在内存里是一段段直线，逻辑上才弯成圆——段末槽与首槽相接的那一刀就是接缝。末槽住不得数据 TRB（xHC 扫到会把它的内容当指令执行），所以固定放一颗 Link TRB 当"回到开头"的路标：

钻点一 · urb → TD → TRB：一次翻译的三层语法

全景图②站说"urb 被改写成 TRB 链"——现在把这台翻译机开盖（六站完整旅程在 0007）。urb 是 usbcore 与 hcd 之间的合同（缓冲地址/长度/回调），TRB 是驱动与 xHC 之间的合同（16 字节定长指令，§4.11.1）。两者粒度差两个数量级，中间隔两层换算：urb 先切成若干 TD（Transfer Descriptor，§4.9.1：xHC 调度与完成事件的最小单位），每个 TD 再切成一串 TRB（CHAIN 位相连，§4.11.7 TD Usage Rules）。urb 切几个 TD，全部规则只有三条（bulk OUT 那条的"补零包"：以零长包收尾一条批量 OUT 是设备侧的普遍期待，内核为此允许"数据 TD＋零包 TD"两段）：

interrupt 与 bulk 在排队和完成路径上完全同构——xhci_queue_intr_tx 整体转发给 xhci_queue_bulk_tx（xhci-ring.c:3496 一行委托），差异全在调度面（周期端点按 bInterval 进入周期调度表，§4.14.3 vs §4.14.4）。段尾还有一个 实现≠规范 的暗坑：若链中间正好要跨 Link TRB，末段数据可能不按包界对齐——xhci_align_td（:3546）用 bounce buffer 把最后一截重新对到 maxp 整数倍（:3700-3707）。

等时：每包一个 TD（prepare_transfer 按包循环调用，:4159-4160）。每个 TD 的首 TRB 是 Isoch TRB 型（§4.11.2.3：携带 TBC/TLBPC 突发字段），其余仍是 Normal TRB。调度属性二选一写在首 TRB 上：SIA（Start Isoch ASAP）= 让 xHC 自排下一个服务区间（§4.11.2.5 p219）；或显式 Frame ID 指定起始帧。内核策略（:3986-4000）：URB_ISO_ASAP 用 SIA；否则仅首 TD 写 Frame ID、后续 TD 仍 SIA——一串包显式定头、其余自动尾随：

			sia_frame_id = (start_uframe + i * uinterval) / 8;
			sia_frame_id = TRB_FRAME_ID(sia_frame_id % MAX_FRAMES);
		} else {
			sia_frame_id = TRB_SIA;
		}
一句话收拢：urb→TD→TRB 是排队时刻的"合同翻译"——TD 数量由传输类型决定（三条规则），TRB 切分由 64K 边界与散列表决定，阶段/突发/调度属性编码进 TRB 位域；完成时刻反向走一遍：Transfer Event 带 TRB 指针→trb_in_td 命中 TD→urb 销账（:877-919）→最后一个 TD 才回调 usbcore。0008 课 M4.5 标本实测的"每门铃一个 TD、短包 TD 两颗事件"，就是这套语法的运行时投影。

chain 这把钥匙单独舞一遍——三帧只看捆绑绳（cycle 全部假设恰好匹配）：

第 1 帧130KB 来了：一颗 TRB 装不下，先切三段货

本帧只看"切"这个动作：一颗 TRB 的 DW0-1 只装得下一个 ≤64K 且不跨边界的缓冲段，130KB 只好切成三颗。但切完只是三段散货，还不是一件行李——把散货打成一件的，是下一帧的 chain。

第 2 帧chain＝捆绑绳：尾 TRB 收口（chain=0）＋完成哨兵（IOC）

本帧只看绳子的两端：中间 TRB 的 chain=1 声明"下一槽与我同属一传"；尾 TRB chain=0＝收口，再搭 IOC 位＝整件的完成哨兵（§4.11.7）。chain 决定"几颗 TRB 算一件"——这就是槽与 TD 的全部关系：槽是车位，chain 把若干车位上的 TRB 打包成一次传输。

第 3 帧xHC 视角：取走链头＝取走整件，事件按"件"发一颗

本帧只看"一口气"：xHC 校验过链头后，沿 chain 一直走到 chain=0 为止——整条链是一个调度与完成单位，事件只发一颗。补充一个预告：TD 中途跨接缝时，缝上的 Link TRB 会被改写 chain 位把绳续上（0007 第 3 章联动动画第 5 帧细看那个场景）。

钻点二 · ring 的几何：segment × 256 槽 × Link TRB × 扩容

三层语法解决了"TD 切成几颗、怎么捆"——还差环的骨架（cycle 轮次的完整合同与事件环 ERST 的分野是 0007 的两个钻点）：多段 segment 怎么拼成环、写满了怎么办。先记三个常数（TRB 16 字节 × 256 = 4096 = 一页，DMA 对齐友好，xhci-mem.c:2440-2448）：

/* xhci.h:1260-1267 */
#define TRBS_PER_SEGMENT	256
/* Allow two commands + a link TRB, along with any reserved command TRBs */
#define MAX_RSVD_CMD_TRBS	(TRBS_PER_SEGMENT - 3)
#define TRB_SEGMENT_SIZE	(TRBS_PER_SEGMENT*16)
#define TRB_SEGMENT_SHIFT	(ilog2(TRB_SEGMENT_SIZE))
/* TRB buffer pointers can't cross 64KB boundaries */
#define TRB_MAX_BUFF_SHIFT		16
#define TRB_MAX_BUFF_SIZE	(1 << TRB_MAX_BUFF_SHIFT)

每段前 255 槽放数据 TRB，第 256 槽固定是 Link TRB（段有效容量 = 段数 × 255，:361）。Link TRB 的内容由初始化写死：类型改写为 TRB_LINK，Buffer Pointer = 下一段首槽的 DMA 地址（xhci-mem.c:97-114）。而 Link TRB 控制字的 Toggle Cycle 位（TC＝DW3 bit1 在 Link TRB 上的身份，xhci.h:958）有一个关键细节——TC 只挂在"整个环最后一段"的 Link TRB 上，中间段的 Link 只跳转、不翻轮次（§4.9.2.1）：多段环转一整圈，cycle_state 只翻一次：

/* xhci-mem.c:105-114（xhci_set_link_trb）段尾 TRB 改写成跳转指令 */
	trb = &seg->trbs[TRBS_PER_SEGMENT - 1];

	/* Set the last TRB in the segment to have a TRB type ID of Link TRB */
	val = le32_to_cpu(trb->link.control);
	val &= ~TRB_TYPE_BITMASK;
	val |= TRB_TYPE(TRB_LINK);
	if (chain_links)
		val |= TRB_CHAIN;
	trb->link.control = cpu_to_le32(val);
	trb->link.segment_ptr = cpu_to_le64(seg->next->dma);
/* xhci-mem.c:129-130 Toggle Cycle 只挂最后一段（§4.9.2.1/§6.4.4.1） */
	/* See section 4.9.2.1 and 6.4.4.1 */
	ring->last_seg->trbs[TRBS_PER_SEGMENT - 1].link.control |= cpu_to_le32(LINK_TOGGLE);

环满了怎么办？——动态扩容（这是传输环区别于命令环/事件环的第三种答案）。prepare_ring（:3268）在每次排队前算空间：enqueue 前方余量不足就调 xhci_ring_expansion（xhci-mem.c:413）再插新段；命令环禁扩（CRCR 游标由硬件持有，软件无权改写它的几何）：

/* xhci-ring.c:3302-3316（prepare_ring） */
	if (ep_ring != xhci->cmd_ring) {
		new_segs = xhci_ring_expansion_needed(xhci, ep_ring, num_trbs);
	} else if (xhci_num_trbs_free(ep_ring) <= num_trbs) {
		xhci_err(xhci, "Do not support expand command ring\n");
		return -ENOMEM;
	}

	if (new_segs) {
		xhci_dbg_trace(xhci, trace_xhci_dbg_ring_expansion,
				"ERROR no room on ep ring, try ring expansion");
		if (xhci_ring_expansion(xhci, ep_ring, new_segs, mem_flags)) {
			xhci_err(xhci, "Ring expansion failed\n");
			return -ENOMEM;
		}
	}

扩容的插法很讲究：新段splice 进 enqueue 所在段之后（不是接在队尾），并保持一条不变量——全环有且只有一个带 TC 的 Link TRB，永远在 last_seg 段尾。新段先按独立小环初始化（新末段带 TC，:429 经 xhci_initialize_ring_segments），拼接后若插入点就是旧末段，就把旧末段的 TC 撤掉、last_seg 指针移交给新末段（xhci-mem.c:169-177）：

/* xhci-mem.c:160-177（xhci_link_rings）——splice + TC 移交 */
	src->last_seg->next = dst->enq_seg->next;
	dst->enq_seg->next = src->first_seg;
	if (dst->type != TYPE_EVENT) {
		chain_links = xhci_link_chain_quirk(xhci, dst->type);
		xhci_set_link_trb(dst->enq_seg, chain_links);
		xhci_set_link_trb(src->last_seg, chain_links);
	}
	dst->num_segs += src->num_segs;

	if (dst->enq_seg == dst->last_seg) {
		if (dst->type != TYPE_EVENT)
			dst->last_seg->trbs[TRBS_PER_SEGMENT-1].link.control
				&= ~cpu_to_le32(LINK_TOGGLE);

		dst->last_seg = src->last_seg;
	} else if (dst->type != TYPE_EVENT) {
		src->last_seg->trbs[TRBS_PER_SEGMENT-1].link.control &= ~cpu_to_le32(LINK_TOGGLE);
	}
一句话收拢：ring = 段链表；段 = 255 数据槽 + 1 Link 槽；Link 携带下段地址，TC 只在 last_seg 段尾出现（唯一轮次翻转点）；传输环可按需 splice 扩段，命令环禁扩，事件环几何外置 ERST。cycle 合同（0007 第 1 章）与 ERST 对照（0007 第 2 章）补上后，三种环的静态几何与动态行为就全部闭环。

toggle cycle（TC）这把钥匙单独舞一遍——三帧只看"轮次什么时候翻"。前置一句就够：每颗 TRB 的 DW3 bit0 是 cycle（所有权签章），软件与 xHC 各记一个"当前轮次"，绕环整整一圈后轮次取反——完整合同在 0007 第 1 章，这里只看翻圈的记账（示意把每段缩成 4+1 槽，真实 255+1）：

第 1 帧两段环＝两道缝，只有最后一段的缝带 TC

本帧只看两颗 Link 的差别：多段环里每段末尾都有一颗 Link（负责段与段拼接），但TC 只挂在整环最后一段——中间段的缝是纯跳转，不翻轮次。

第 2 帧转一圈：跨两道缝，轮次只翻一次

本帧只看轮次盒：跨中间缝①什么都不发生（纯跳转），跨末段缝②轮次才翻。生产/消费两侧各翻各的——软件在 inc_enq_past_link（:254-260），xHC 在跨缝取指时——两侧从不同步全局状态，只在各自的缝上翻各自的账。

第 3 帧反例：若两道缝都带 TC——翻两次＝白翻

本帧只看"为什么不能两颗都带 TC"：翻两次等于白翻——轮次回到原值后，上一圈残影的 cyc 恰与轮次相同，会被当成新货（假有效）。所以规范把翻轮次的权力收归整环唯一一道缝。
