①规范与代码分析

规范要点（xHCI 规范 §4.3 · p71-80）

要点 1 · FS 设备先经 EP0 读 Device Descriptor 前 8 字节取 bMaxPacketSize0

For FS devices, system software should initially read the first 8 bytes of the USB Device Descriptor to retrieve the value of the bMaxPacketSize0 field and determine the actual Max Packet Size for the Default Control Endpoint, by issuing a USB GET_DESCRIPTOR request to the device, update the Default Control Endpoint Context with the actual Max Packet Size and inform the xHC of the context change. Step a describes this operation.
对 FS 设备，系统软件应先读取 USB 设备描述符（Device Descriptor）的前 8 字节，以取得 bMaxPacketSize0 字段的值，从而确定默认控制端点的实际 Max Packet Size（最大包大小）——做法是向设备发出 USB GET_DESCRIPTOR 请求，用实际 Max Packet Size 更新默认控制端点上下文（Default Control Endpoint Context），并把该上下文变更告知 xHC。步骤 a 描述了这一操作。
—— evidence/spec-43.txt L103-L107（p72）

要点 2 · 控制传输三段顺序：Setup → Data → Status（shall 要求）

The USB GET_DESCRIPTOR request requires a Data Stage, so the Setup Stage TD shall be followed by a Data Stage TD, then a Status Stage TD.
a. USB GET_DESCRIPTOR 请求需要数据阶段（Data Stage），因此 Setup Stage TD 之后应跟一个 Data Stage TD，再跟一个 Status Stage TD。为此软件应：
—— evidence/spec-43.txt L115-L116（p73）

要点 3 · Setup Stage TRB 字段：TRT=IN Data Stage(3)/Length=8/IOC=0/IDT=1/bmRequestType=80h/bRequest=6/wValue=0100h/wLength=8

Initialize the Setup Stage TD (a single Setup Stage TRB) on the Endpoint 0 Transfer Ring. • TRB Type = Setup Stage TRB. • Transfer Type (TRT) = IN Data Stage (3). • TRB Transfer Length = 8. • Interrupt On Completion (IOC) = 0. • Immediate Data (IDT) = 1.
ii. 在端点 0 传输环（Endpoint 0 Transfer Ring）上初始化 Setup Stage TD（单个 Setup Stage TRB）。• TRB Type = Setup Stage TRB。• Transfer Type（TRT）= IN Data Stage（3）。• TRB Transfer Length = 8。• Interrupt On Completion（IOC）= 0。• Immediate Data（IDT）= 1。• bmRequestType = 80h。
—— evidence/spec-43.txt L120-L125（p73）

要点 4 · 三段就绪后敲设备槽门铃：DB Target = Control EP 0 Enqueue Pointer Update

Ring the Device Slots’ Doorbell with DB Target = Control EP 0 Enqueue Pointer Update.
viii. 敲响该 Device Slot 的门铃，DB Target = Control EP 0 Enqueue Pointer Update。
—— evidence/spec-43.txt L181（p74）

要点 5 · Address Device 命令完成后才能对该槽发更多命令（等待语义）

System software shall wait for Address Device Command completion event on the Event Ring before issuing any more commands to the slot.
在向该槽发出更多命令之前，系统软件应在事件环上等待 Address Device Command 完成事件。
—— evidence/spec-43.txt L346（p76）

    usb: xhci: Set avg_trb_len = 8 for EP0 during Address Device Command
    
    There is a subtle contradiction between sections of the xHCI 1.2 spec
    regarding the initialization of Input Endpoint Context fields. Section
    4.8.2 ("Endpoint Context Initialization") states that all fields should
    be initialized to 0. However, Section 6.2.3 ("Endpoint Context", p.453)
    specifies that the Average TRB Length (avg_trb_len) field shall be
    greater than 0, and explicitly notes (p.454): "Software shall set
    Average TRB Length to '8' for control endpoints."
    
    Strictly setting all fields to 0 during initialization conflicts with
    the specific recommendation for control endpoints. In practice, setting
    avg_trb_len = 0 is not meaningful for the hardware/firmware, as the
    value is used for bandwidth calculation.
    
    Motivation: Our company is developing a custom Virtual xHC hardware
    platform that strictly follows the xHCI spec and its recommendations.
    During validation, we observed that enumeration fails and a parameter
    error (TRB Completion Code = 5) is reported if avg_trb_len for EP0 is
    not set to 8 as recommended by Section 6.2.3. This demonstrates the
    importance of assigning a meaningful, non-zero value to avg_trb_len,
    even in virtualized or emulated environments.
    
    This patch explicitly sets avg_trb_len to 8 for EP0 in
    xhci_setup_addressable_virt_dev(), as recommended in Section 6.2.3, to
    prevent potential issues with xHCI host controllers that enforce the
    spec strictly.

背景（何时 / 何硬件 / 谁报）

2025 年 7 月，Jay Chen 报告：其公司正在开发一个严格遵循 xHCI 规范的自研虚拟 xHC 硬件平台，验证阶段设备枚举失败——Address Device 命令回 TRB Completion Code = 5（Parameter Error），bug 单在 kernel bugzilla 220033。根因不在虚拟平台自身，而是 Linux 驱动对规范两处条文的取舍：初始化输入端点上下文时全字段清零，其中 Average TRB Length（avg_trb_len）= 0，而严格按规范实现的控制器会判定该参数非法。主流真实硬件恰好不校验这个字段，问题因此在真机上从未暴露——虚拟平台反而成了规范的忠实裁判。对应课程 4.3 的 Address Device 输入上下文节拍。

要解决的问题（症状 + 机制）

症状：严格按规范实现的（虚拟）xHC 在 EP0 编址时返回 Parameter Error（完成码 5），设备枚举失败。机制：规范 §4.8.2（Endpoint Context Initialization）要求输入端点上下文所有字段初始化为 0；§6.2.3（Endpoint Context）却规定 Average TRB Length 应大于 0，且明确「Software shall set Average TRB Length to 8 for control endpoints」——两条条文在全 0 初始化面前互相矛盾。avg_trb_len 用于带宽计算，对控制端点填 0 没有意义。驱动此前按 §4.8.2 字面义把 EP0 的 avg_trb_len 留成 0：宽容的硬件忽略它，严格的硬件判错。课程侧对应证据：§4.3.3（p76）「Allocate an Input Context data structure (6.2.5) and initialize all fields to 0」之后逐字段初始化 EP0 Context——补丁即在这条全 0 路径上为控制端点开例外。
