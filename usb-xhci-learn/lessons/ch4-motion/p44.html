    usb: xhci: Fix memory leak in xhci_disable_slot()
    
    xhci_alloc_command() allocates a command structure and, when the
    second argument is true, also allocates a completion structure.
    Currently, the error handling path in xhci_disable_slot() only frees
    the command structure using kfree(), causing the completion structure
    to leak.
    
    Use xhci_free_command() instead of kfree(). xhci_free_command() correctly
    frees both the command structure and the associated completion structure.
    Since the command structure is allocated with zero-initialization,
    command->in_ctx is NULL and will not be erroneously freed by
    xhci_free_command().
    
    This bug was found using an experimental static analysis tool we are
    developing. The tool is based on the LLVM framework and is specifically
    designed to detect memory management issues. It is currently under
    active development and not yet publicly available, but we plan to
    open-source it after our research is published.
    
    The bug was originally detected on v6.13-rc1 using our static analysis
    tool, and we have verified that the issue persists in the latest mainline
    kernel.
    
    We performed build testing on x86_64 with allyesconfig using GCC=11.4.0.
    Since triggering these error paths in xhci_disable_slot() requires specific
    hardware conditions or abnormal state, we were unable to construct a test
    case to reliably trigger these specific error paths at runtime.

背景（何时 / 何硬件 / 谁报）

2026 年 3 月，东南大学 Zilin Guan 以基于 LLVM 框架的实验性静态分析工具发现并提交（工具随论文研发中，bug 最初在 v6.13-rc1 检出、主线仍在）；x86_64 allyesconfig、GCC 11.4.0 构建验证。这两条错误路径要求 host 已死或命令入环失败等异常状态才走到，难以构造运行时用例稳定触发，属「静态分析发现 + 构建验证」类交付。对应 §4.4 拔除链的下半程：设备拔除（PORTSC CCS 清 0 / CSC 置 1，p81）→ 端口变化事件 → usbcore 调 xhci_free_dev → xhci_disable_slot——控制器异常时走的正是被修的两条错误返回路径。

要解决的问题（症状 + 机制）

症状：xhci_disable_slot() 的两条错误路径（host 控制器已死 / Disable Slot 命令入环失败）各泄漏一个 completion 结构。机制：L4151 的 xhci_alloc_command(xhci, true, GFP_KERNEL) 第二参为 true 时，除命令结构外还分配 completion 结构；错误路径只用 kfree(command) 释放命令结构本身，completion 结构泄漏。规范背景（§4.4 p81）：检出拔除后软件须对受影响槽发 Disable Slot Command——若控制器恰在此刻死亡，命令发出前就返回，每次异常拔除都留下一个孤儿 completion。

代码逻辑（补丁前 → 后行为对照）

把两条错误路径的 kfree(command) 改为 xhci_free_command(xhci, command)（+2/-2）：后者同时释放命令结构与关联的 completion 结构；命令结构零初始化使 command->in_ctx 为 NULL，不会被误释放。补丁前：kfree 只放一半，completion 泄漏；补丁后：错误路径与成功路径（L4183）释放形态统一，任何退出路径都不留孤儿。与贴码对读：det:1 分配行（true=带 completion）、det:5 热行即被改的错误路径之一——本补丁已在基线 d9008e061539 内，贴码即补丁后形态；§4.4 拔除剧本的「异常退出」分支从此与正常分支同构。
