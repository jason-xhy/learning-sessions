4.7Doorbells 门铃机制p142-p143

规范引文（机制主线）

The xHCI presents an array of up to 256 32-bit Doorbell Registers (refer to section 5.6), which reside in MMIO space and are indexed by Device Slot ID. The base of the Doorbell Register Array is pointed to by the Doorbell Offset (DBOFF) register in the xHCI Capability Registers (refer to section 5.3.7). Each Doorbell Register contains a DB Target field, which is used to indicate the reason for a software reference to the register. System software “rings” a doorbell by writing a Doorbell Register with the appropriate value in the DB Target field.
xHCI 提供了最多 256 个 32 位门铃寄存器（Doorbell Register）构成的数组（参见第 5.6 节），这些寄存器驻留在 MMIO 空间中，并以 Device Slot ID 为索引。门铃寄存器数组的基址由 xHCI 能力寄存器（xHCI Capability Registers）中的门铃偏移（Doorbell Offset，DBOFF）寄存器指向（参见第 5.3.7 节）。 每个门铃寄存器都包含一个 DB Target 字段，用于指示软件访问该寄存器的原因。系统软件通过向门铃寄存器写入、并在 DB Target 字段中填入适当取值来“振铃”（ring）一个门铃。
—— evidence/spec-47.txt L3-L10（p142）
Doorbell Register 0 is dedicated to the Host Controller. For this register, there is only one valid value for the DB Target field, 0 (Host Controller Command). The remaining values (1-255) are reserved.
门铃寄存器 0 专用于主机控制器。对于该寄存器，DB Target 字段只有一个有效取值，即 0（Host Controller Command）。其余取值（1-255）为保留值。
—— evidence/spec-47.txt L11-L13（p142）
Doorbell Registers 1-255 are referred to as the Device Context Doorbell registers. There is a 1:1 mapping of Device Context Doorbell registers to Device Slots. System software rings a Device Context Doorbell after it has inserted work on a Transfer Ring (endpoint/Stream) associated with the respective Device Slot. The DB Target and DB Stream ID fields of a Device Context Doorbell register is used to identify which Transfer Ring of a device has been modified. Refer to Table 5-43 for the encoding of the DB Target field.
门铃寄存器 1-255 被称为设备上下文门铃寄存器（Device Context Doorbell Register）。设备上下文门铃寄存器与设备槽位之间存在 1:1 映射。在向与相应设备槽位关联的某个传输环（端点/流）插入工作之后，系统软件才振铃设备上下文门铃。设备上下文门铃寄存器的 DB Target 与 DB Stream ID 字段用于标识设备的哪个传输环被修改。DB Target 字段的编码参见表 5-43。
—— evidence/spec-47.txt L14-L20（p142）
The xHC internally records all Doorbell Register write references and uses the information to determine if the Command Ring or a Transfer Ring has newly posted work items (TDs). There is no need to “clear” a Doorbell Register. To inform the xHC that work has been posted to two separate Transfer Rings of a device, system software shall post two writes to the associated Doorbell Registers, where the value of the DB Target field identifies the respective Transfer Ring.
xHC 会在内部记录所有门铃寄存器写入引用，并利用该信息来判定命令环或某个传输环是否新投递了工作项（TD）。无需“清除”门铃寄存器。为通知 xHC 已向一个设备的两个独立传输环投递了工作，系统软件必须向相应的门铃寄存器发出两次写入，其中 DB Target 字段的值标识各自的传输环。
—— evidence/spec-47.txt L27-L33（p143）
Software shall not write to a Doorbell register: • If the associated Device Slot is in the Disabled state. • If the associated Device Slot is not in the Disabled state and the DB Target field is set to an endpoint that is in the Disabled state. If a doorbell register is written by software with the DB Target value that references an endpoint that is in the Disabled state, the xHC should generate a Transfer Event TRB with the TRB Pointer, TRB Transfer Length, Event Data (ED) fields set to ‘0’, a Completion Code of Endpoint Not Enabled Error, and the Slot ID and Endpoint ID fields contain the IDs of device slot/endpoint that the doorbell that was rung for. This transfer Event TRB shall be posted to the Primary Event Ring.
软件不得在以下情况下向门铃寄存器写入： - 关联的设备槽位处于 Disabled 状态。 - 关联的设备槽位不处于 Disabled 状态，而 DB Target 字段被置为处于 Disabled 状态的某个端点。 若软件向门铃寄存器写入的 DB Target 取值引用了处于 Disabled 状态的端点，则建议 xHC 生成一个传输事件 TRB（Transfer Event TRB），其 TRB Pointer、TRB Transfer Length、Event Data（ED）字段被置为 ‘0’，Completion Code 为 Endpoint Not Enabled Error，且 Slot ID 与 Endpoint ID 字段包含被振铃门铃所对应的设备槽位/端点的 ID。该传输事件 TRB 必须被投递到主事件环（Primary Event Ring）。
—— evidence/spec-47.txt L35-L47（p143）
An Endpoint Not Enabled Error should be generated for doorbell register writes to Device Slots that are in the Disabled state regardless of the DB Target value provided. The xHC may ignore doorbell references to Device Slots in the Disabled state or endpoints in the Disabled state. The xHC shall ignore doorbell references to endpoints in the Halted or Error state.
对于向处于 Disabled 状态的设备槽位发出的门铃寄存器写入，无论提供的 DB Target 取值如何，都建议生成 Endpoint Not Enabled Error。 xHC 可以忽略指向处于 Disabled 状态的设备槽位或处于 Disabled 状态的端点的门铃引用。 xHC 必须忽略指向处于 Halted 或 Error 状态端点的门铃引用。
—— evidence/spec-47.txt L48-L54（p143）

背景（何时 / 谁修 / 为什么是它）

2013 年 7 月，Oleksij Rempel 提交。场景（message 原文）：设备挂在 xHCI 口上但不响应——举例 ath9k_htc 固件停摆——内核在 ring_doorbell_for_active_rings() 里崩溃。对应 §4.7 门铃机制：软件放好工作后敲门铃、xHC 记录写引用判断新 TD——本卡贴码段（L585-L607）正是这条路径的内核侧。

要解决的问题（症状 + 机制）

症状：空指针解引用内核崩溃。机制：函数对每个「有挂起 TD」的环敲门铃（函数注释原文 "A ring has pending URBs if its TD list is not empty"）；但走到非流端点分支时 ep->ring 可能为 NULL（端点尚无环），&ep->ring->td_list 一取址即崩。

代码逻辑（补丁前 → 后行为对照）

用前判空：if (ep->ring && !(list_empty(&ep->ring->td_list)))——有环且有挂起 TD 两条件都成立才敲。规范对齐：§4.7 p142 "System software rings a Device Context Doorbell after it has inserted work on a Transfer Ring"——ep->ring 为 NULL 时连关联的 Transfer Ring 都不存在，判空把敲铃收回到「有工作才敲」的规范语义内。对读注记：修复行=基线 L595，恰在本卡上方贴码段（L585-L607）内——贴码即补丁后形态，故无独立对读段（ch4610p 先例）；分帧走读见 xh0700p（scene=57）。
