      剧本：把 xHC 从复位带到开机（R/S=1）

      就绪门：「After Chip Hardware Reset wait until the Controller Not Ready (CNR) flag in the USBSTS is ‘0’ before writing any xHC Operational or Runtime registers.」（§4.2 p69）

      顺序门：「This text does not imply a specific order for the following operations, however these operations shall be completed before setting the USBCMD register Run/Stop (R/S) bit to ‘1’.」（§4.2 p69 Note）

      点卡片，按你认为合法的顺序完成寄存器编程：①「等 CNR=0」必须最先（就绪前不许写任何 Operational/Runtime 寄存器）；②「USBCMD R/S=1」必须最后（其余没做完不许开机）；③ 中间五步顺序随意——规范明文不强制。每张卡完成后展开该步的规范原文；七步全部完成后，每张卡会标注 Linux 内核（基线 d9008e061539）实际编程的顺序。

      ✓ 主机控制器已开机（R/S=1）——「This operation allows the xHC to begin accepting doorbell references.」（§4.2 p70）。根端口开始上报设备连接，可以按 §4.3 枚举设备 → 去模块一走 Enable Slot 命令闭环。
      Linux 内核（基线 d9008e061539）实际编程顺序：xhci_gen_setup → xhci_reset（等 CNR=0，xhci.c L229/L5516）→ xhci_init（xhci.c L531）内 ① MaxSlotsEn → ② CRCR → ③ DCBAAP → ④ ERSTSZ → ERSTBA（xhci_add_interrupter，xhci-mem.c L2343/L2351）→ xhci_run_finished 内 xhci_start（R/S=1，xhci.c L154/L599）。中间五步内核自选次序 = MaxSlotsEn → CRCR → DCBAAP → ERSTSZ → ERSTBA——规范不强制，内核有自己的工程顺序。
      从「等 USBSTS.CNR=0」开始：先点它。

      场景：FS 设备 · GET_DESCRIPTOR（Device Descriptor 前 8 字节）

      「For FS devices, system software should initially read the first 8 bytes of the USB Device Descriptor to retrieve the value of the bMaxPacketSize0 field」（§4.3 p72 步7）——LS/HS/SS 设备（8/64/512 字节）可跳过此步。

      「The USB GET_DESCRIPTOR request requires a Data Stage, so the Setup Stage TD shall be followed by a Data Stage TD, then a Status Stage TD.」（§4.3 p73 a）——控制传输三段：Setup → Data → Status；本例每段 TD 恰好一个 TRB（a single Setup/Data/Status Stage TRB，§4.3 p73 ii/iv/vi）。

          Zone B · DCI 计算器（§4.5.1 Device Context Index）

          DCI 公式（常驻）——「For Isoch, Interrupt, or Bulk type endpoints the DCI is calculated from the Endpoint Number and Direction with the following formula; DCI = (Endpoint Number * 2) + Direction, where Direction = ‘0’ for OUT endpoints and ‘1’ for IN endpoints.」（§4.5.1 · evidence/spec-45.txt L96-99）「For Control type endpoints: DCI = (Endpoint Number * 2) + 1.」（§4.5.1 · spec-45.txt L101-102）另：Slot Context 自身占 DCI=0——「The DCI of the Slot Context is 0.」（spec-45.txt L93）DCI 取值范围 0-31（31 个 Endpoint Context，spec-45 L90-92）。

          选 EP 号/方向/类型，实时算 DCI（下方出公式展开）。
          EP0 特例（Control EP0 → DCI=1）：Endpoint Context 0 恒为设备的 Default Control Endpoint（双向，方向不参与）——「Note that Endpoint Context 0 is always associated with the Default Control Endpoint of the device.」（§4.5 · spec-45.txt L69-70）；Slot Context 占 DCI=0（「The DCI of the Slot Context is 0.」L93），EP0 按控制公式 DCI=(0*2)+1=1（L101-102）——所以 Device Context 里 EP0 紧跟 Slot Context 之后的第 1 个 Endpoint Context。
