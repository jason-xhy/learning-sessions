4.8.1Endpoint Addressing 端点寻址机制p143-p144

规范引文（机制主线）

A USB device supports up to 31 endpoints (EPs): for example,15 IN, 15 OUT, and 1 Control. The Default Control EP (0) is a bidirectional EP defined for all USB devices.
一个 USB 设备最多支持 31 个端点（EP）：例如 15 个 IN、15 个 OUT 和 1 个 Control。默认控制 EP（0）是为所有 USB 设备定义的双向 EP。
—— evidence/spec-48.txt L3-L5（p143）
An Endpoint Address defined by a USB Endpoint Descriptor allows up to 31 possible values, where a 4-bit Endpoint Number is combined with a Direction bit (refer to section 9.6.6 in the USB2 spec). The xHCI parallels this organization by using the Endpoint Number to select one of 16 Endpoint Context data structure pairs, and the Direction bit to select the IN or OUT Endpoint Context of a pair. Refer to Figure 4-4 to the right.
由 USB 端点描述符（Endpoint Descriptor）定义的端点地址（Endpoint Address）最多允许 31 个可能的取值，其中 4 位的端点号（Endpoint Number）与一个方向位（Direction bit）组合而成（参见 USB2 规范第 9.6.6 节）。xHCI 仿照这一组织方式：用端点号从 16 对端点上下文（Endpoint Context）数据结构对中选出一对，再用方向位选出该对中的 IN 或 OUT 端点上下文。参见图 4-4（位于右侧）。
—— evidence/spec-48.txt L41-L46（p144）
A Control endpoint (for example, EP Number 0 in Figure 4-4) is a bidirectional endpoint and, per the USB specification, the Direction bit is “ignored” when calculating its Endpoint Address, that is, only the Endpoint Number is used to calculate the location of a Control Endpoint Context data structure. To accommodate the addressing anomaly of USB bidirectional endpoint addressing the xHC shall use the IN (odd) Endpoint Context of the pair to manage bidirectional endpoints.
控制端点（例如图 4-4 中的 EP 号 0）是双向端点；按照 USB 规范，在计算其端点地址时方向位被“忽略”，也就是说，只用端点号来计算控制端点上下文（Control Endpoint Context）数据结构的位置。为兼容 USB 双向端点寻址的这一反常之处，xHC 必须使用该对中的 IN（奇数）端点上下文来管理双向端点。
—— evidence/spec-48.txt L47-L53（p144）
The USB specification allows a device to define additional Control (bidirectional) endpoints, beyond the Default Control Endpoint (EP 0) required by the USB Framework. Using the rules defined above, the xHCI is capable of supporting additional Control endpoints.
USB 规范允许设备在 USB 框架所要求的默认控制端点（EP 0）之外，定义额外的控制（双向）端点。按照上述规则，xHCI 能够支持这些额外的控制端点。
—— evidence/spec-48.txt L54-L57（p144）
For all Endpoint Numbers greater than 0, the xHC shall ignore the OUT (even) Endpoint Context of the pair of any endpoint that declares itself as a bidirectional. Software shall use the IN (odd) Endpoint Context of a pair for managing a Control Endpoint.
对于所有大于 0 的端点号，若某端点声明自身为双向，则 xHC 必须忽略其对中 OUT（偶数）端点上下文。软件必须使用一对中的 IN（奇数）端点上下文来管理控制端点。
—— evidence/spec-48.txt L58-L61（p144）

4.8.3Endpoint Context State 端点上下文状态机制p146-p149

规范引文（机制主线）

The current state of an Endpoint Context is identified by its respective Endpoint State (EP State) field. Figure 4-5 defines the Endpoint States.
端点上下文（Endpoint Context）的当前状态由其相应的端点状态（Endpoint State，EP State）字段标识。图 4-5 定义了各端点状态。
—— evidence/spec-48.txt L161-L162（p146）
1. The Address Device Command transitions the Default Control Endpoint from the Disabled to the Running state. 2. The Configure Endpoint Command (Add (A)= ‘1’and Drop (D) = ‘0’) shall transition an endpoint, except the Default Control Endpoint, from the Disabled to the Running state. 3. The Configure Endpoint Command (Add (A)= ‘0’ and Drop (D) = ‘1’) or Reset Device Command shall transition an endpoint, from any state to the Disabled state, except the Default Control Endpoint which may transition from the Stopped to the Running state or remain in the Stopped state.
1. Address Device 命令（寻址设备命令）使默认控制端点从 Disabled 状态迁移到 Running 状态。 2. Configure Endpoint 命令（Add (A) = ‘1’ 且 Drop (D) = ‘0’）必须使除默认控制端点之外的端点从 Disabled 状态迁移到 Running 状态。 3. Configure Endpoint 命令（Add (A) = ‘0’ 且 Drop (D) = ‘1’）或 Reset Device 命令必须使一个端点从任何状态迁移到 Disabled 状态；但默认控制端点例外——它可以从 Stopped 状态迁移到 Running 状态，或保持停留在 Stopped 状态。
—— evidence/spec-48.txt L170-L178（p146）
4. The Disable Slot Command shall transition all endpoints of a Device Slot, including the Default Control Endpoint, from any state to the Disabled state. 5. In the Running state, a Set TR Dequeue Pointer Command should only be issued to the non-active Transfer Rings of a Stream endpoint. Refer to section 4.12 for active vs. non-active Stream Context information. 6. The Configure Endpoint Command (Add (A) = ‘1’ and Drop (D) = ‘1’) shall transition an endpoint, except the Default Control Endpoint, from the Stopped to the Running state. 7. In the Stopped state, a Set TR Dequeue Pointer Command may be used to modify the starting TRB of an endpoint or non-active Stream prior to ringing the Doorbell. Refer to section 4.12 for active vs. non-active Stream Context information.
4. Disable Slot 命令必须使一个设备槽位的所有端点（包括默认控制端点）从任何状态迁移到 Disabled 状态。 5. 在 Running 状态下，Set TR Dequeue Pointer 命令建议只发给流端点（Stream endpoint）的非活动传输环。活动与非活动流上下文（Stream Context）信息参见第 4.12 节。 6. Configure Endpoint 命令（Add (A) = ‘1’ 且 Drop (D) = ‘1’）必须使除默认控制端点之外的端点从 Stopped 状态迁移到 Running 状态。 7. 在 Stopped 状态下，可以在振铃门铃之前使用 Set TR Dequeue Pointer 命令来修改端点或非活动流（Stream）的起始 TRB。活动与非活动流上下文信息参见第 4.12 节。
—— evidence/spec-48.txt L185-L195（p147）
Figure 4-5 illustrates the state transitions presented by an endpoint. The Disabled to Running transition for the Default Control Endpoint shall occur due to an Address Device Command, and for all other endpoints the transition shall be invoked by a Configure Endpoint Command. Refer to Appendix E for state machine notation. A Halt condition, for example, a Stall Error, Invalid Stream Type Error, Invalid Stream ID Error, Babble Detected Error, Event Lost Error, USB Transaction Error, or a Split Transaction Error detected on a USB pipe shall cause a Running Endpoint to transition to the Halted state. A Reset Endpoint Command shall be used to clear the Halt condition on the endpoint and transition the endpoint to the Stopped state. 图 4-5 图示了端点所呈现的状态迁移。默认控制端点从 Disabled 到 Running 的迁移必须由 Address Device 命令引发；对所有其他端点，该迁移必须由 Configure Endpoint 命令触发。状态机记法参见附录 E。 在 USB 管道上检测到的 halt（停机）条件——例如 Stall Error、Invalid Stream Type Error、Invalid Stream ID Error、Babble Detected Error、Event Lost Error、USB Transaction Error 或 Split Transaction Error——必须使处于 Running 的端点迁移到 Halted 状态。必须使用 Reset Endpoint 命令来清除端点上的 halt 条件，并把端点迁移到 Stopped 状态。端点处于 Halted 状态期间收到的 Stop Endpoint 命令不得产生任何效果，且必须生成一个 Completion Code 被置为 Context State Error 的命令完成事件（Command Completion Event）。
—— evidence/spec-48.txt L196-L209（p147）
Note: A STALL detected on any stage (Setup, Data, or Status) of a Default Control Endpoint request shall transition the Endpoint Context to the Halted state. A Default Control Endpoint STALL condition is cleared by a Reset Endpoint Command which transitions the endpoint from the Halted to the Stopped state. The Default Control Endpoint shall return to the Running state when the Doorbell is rung for the next Setup Stage TD sent to the endpoint. Section 8.5.3.4 of the USB2 spec and section 8.12.2.3 of the USB3 spec state of Control pipes, “Unlike the case of a functional stall, protocol stall does not indicate an error with the device.” The xHC treats a functional stall and protocol stall identically, by Halting the endpoint and requiring software to clear the condition by issuing a Reset Endpoint Command. Note: If the STALL condition is detected on the Setup or Data Stage TD of a request, software shall be responsible for removing the Data Stage or Status Stage TDs, respectively, associated with the request from the Transfer Ring.

—— evidence/spec-48.txt L304-L320（p149）

背景（何时 / 谁修 / 为什么是它）

2020 年 6 月，Intel Mathias Nyman 提交。EP_STATE_MASK 是从端点上下文提取 EP State 的掩码（消费者 GET_EP_CTX_STATE，基线 L462）；§4.8.3 定义端点上下文状态（Figure 4-5 五态：Disabled/Running/Halted/Stopped/Error），状态值落在 EP State 域。

要解决的问题（症状 + 机制）

症状：掩码 0xf=b1111 比 EP State 域（bits[2:0]）多罩一位——bit 3 属域外邻域位，按域布局是 RsvdZ（恒 0），message 原文自评 "hopefully this hasn't caused too much harm"（幸而无害的勘误）。

代码逻辑（补丁前 → 后行为对照）

一行勘正 0xf→0x7：b0111 恰罩 bits[2:0]；五态值 0-4+5-7 保留，恰好填满三位域。位宽权威=补丁 message 引 spec 6.2.3 域布局（第 6 章，出本章界——章界口径注记不展开）；下方对读段注释头 L448 "Endpoint State - bits 0:2" 与 L454 "5-7 - reserved" 即内核侧域宽双证。分帧走读见 xh0803p（scene=58）。
