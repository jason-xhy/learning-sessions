    usb: xhci: Fix slot_id resource race conflict
    
    xHC controller may immediately reuse a slot_id after it's disabled,
    giving it to a new enumerating device before the xhci driver freed
    all resources related to the disabled device.
    
    In such a scenario, device-A with slot_id equal to 1 is disconnecting
    while device-B is enumerating, device-B will fail to enumerate in the
    follow sequence.
    
    1.[device-A] send disable slot command
    2.[device-B] send enable slot command
    3.[device-A] disable slot command completed and wakeup waiting thread
    4.[device-B] enable slot command completed with slot_id equal to 1 and
                 wakeup waiting thread
    5.[device-B] driver checks that slot_id is still in use (by device-A) in
                 xhci_alloc_virt_device, and fail to enumerate due to this
                 conflict
    6.[device-A] xhci->devs[slot_id] set to NULL in xhci_free_virt_device
    
    To fix driver's slot_id resources conflict, clear xhci->devs[slot_id] and
    xhci->dcbba->dev_context_ptrs[slot_id] pointers in the interrupt context
    when disable slot command completes successfully. Simultaneously, adjust
    function xhci_free_virt_device to accurately handle device release.

背景（何时 / 何硬件 / 谁报）

2025 年 8 月，兆芯（Zhaoxin）Weitao Wang 报告并修复；Fixes 追溯 7faac1953ed1（disable slot 与运行时挂起竞态修复引入的形态）。场景：device-A（slot_id=1）正在断开、device-B 正在枚举——xHC 对「同一 slot_id 先 disable 再 enable」的复用没有软件可见的延迟承诺，控制器可以在 disable 完成的瞬间就把刚释放的 slot_id 分给新设备。

要解决的问题（症状 + 机制）

六步竞态时序（补丁信息原文）：① A 发 Disable Slot；② B 发 Enable Slot；③ A 的 Disable 完成并唤醒等待线程；④ B 的 Enable 完成且拿到的正是 slot_id=1；⑤ B 在 xhci_alloc_virt_device 检查 xhci->devs[1] 仍被 A 占用 → 枚举失败；⑥ A 的 xhci_free_virt_device 才把 devs[1] 置 NULL——永远晚一步。规范背景：Table 4-1（p86）Disabled 态 DCBAA 指针无效、槽不可用——驱动侧软件镜像（devs[] / DCBAA）必须与 xHC 的槽状态同步翻转，而原实现把它们留到进程上下文的慢路径。
